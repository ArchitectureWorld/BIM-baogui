# HIFC-Web 主线同步核查（2026-10-19）

本轮按用户要求，将最新 `main` 的 `0.4.4` 更新合入 Web，并将独立分支统一为 `HIFC-Web`，用于本地与 GitHub 同步。同步前 Web 为 `0b72fed`，核实的远程主线为 `337bbcc4cbcefa197170b35a61f46f9d20c85a64`。

## 同步范围与版本

主线新增的地下区域规则、地下指标核心、载体与单位修正、测试和发布记录按原内容合入。`V1/src`、`V1/tools`、冻结参考文件、Local 构建属性及原有 CI 与该主线提交完全一致；本轮额外适配只在 `V1/web` 中。

| 内容 | 本轮源码版本 |
|---|---|
| main / Local 产品 | 0.4.4 |
| Local 程序集 | 0.4.4.0 |
| Web 产品 | 0.5.0 |
| Web 自有程序集 | 0.5.0.0 |
| Web 规则来源 | reference-0.4.4-web1 |
| Web 协议主版本 | 1，DTO 与既有签名格式保持 |

Web 产品版本与其复用的规则来源分别标识；本轮不把 Web 改成 Local 的版本，也不改动既有 `0.5.0-dev-*` 更新通道、下载地址和安装目录。两版 AddInId 保持独立。

## 已修正的兼容问题

- 新盘点拒绝旧 `0.4.3` 规则标识；已保存的字段取数不能交由不同规则版本重新计算。
- 地下建筑层数通过核心的 `ExportType` 以 `Integer` 进入 Web 编辑和写入方案，冻结原始契约仍保留原有 `Integerl` 证据。
- 人防区域、消防分区、停车场和停车位沿用主线的 Revit Area 载体要求。房间虽然也可能是 IfcSpace，仍只显示核对原因，不生成区域写入字段，也不能通过人工分类绕过载体要求。
- 对具有投影面积字段的 Area 类目，使用客户端已有的实际平方米面积，并显示来源；兼容旧客户端未上传几何投影面积的情况。未放置、零面积及有模型问题的对象不据此生成面积建议。停车位继续使用原契约的车位字段。
- 来源或载体需要核对的对象计入复核数量，输入盘点数据不被服务器改写。
- 补齐服务端 JSON 适配器按运行时类型反序列化的方法，使主线新增地下指标用例能在 .NET 10 中执行；保留长度限制、BOM 处理和字段读取约定。

本轮没有增加 Web 的“地下楼层 / 基准”确认界面。地下指标可以按核心字段类型手工编辑；没有通过楼层名称或负标高自动推定层数和高度。
