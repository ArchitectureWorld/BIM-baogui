## 实施边界

- 使用现有 Web worktree 和 HIFC-Web 分支。原 Local checkout、未提交工作、正式安装、浏览器状态、数据库及原 RVT 留在原地。
- 先合入已发布 main，再把正式 0.4.20 必需的未提交源码按明确文件清单复制到 Web worktree；记录文件 SHA256、来源和版本。跨目录仅同步 Local 原内容，Web 适配代码放在 `V1/web`。
- 必需的新源码包括 `V1/platform-sync/src/real-*.ts`、`report.ts`、`worker.ts`、`PlatformSyncWindow.Layout.cs` 及其依赖和测试。排除 `.runtime`、浏览器 profile、凭据、SQLite、客户文件、outputs、dist、bin/obj 与临时验证目录。
- Revit 宿主为 2020 / net48，规则服务继续用现有 .NET 服务；RVT 留在用户电脑。业务规则、冻结规则资源及整轮计算保留在服务端。
- Web 与 Local 共用模型业务参数及已定义的 RVT 资料 schema；账号、桌面偏好、平台登录、浏览器、绑定和任务状态使用 Web 自己的目录。

## 方案选择

推荐完整能力同步：保留现有六文件主包，通过新增的独立签名组件通道分发 Node 与平台同步程序。旧客户端可以按既有机制更新主包；新安装器或新客户端自动补齐组件，不要求同事手装依赖。

已排除两种不足的做法：只改规则版本无法补齐 Web 的原生写入、资料和导出能力；直接把 Node 和运行目录加入现有主包文件清单会被旧更新器拒绝。若扩展主包协议，则需要过渡版本或重装，本轮采用独立组件以保留现有升级路径。

## 协议、版本和数据保护

- 本轮沿用 Web `0.5.0` 独立开发线，发行 ID 递增；主包 Format=1、原六个载荷文件、签名身份、AddInId 和更新目录保持兼容。
- 模型业务协议提升为 `ProtocolMajor=2`，规则标识为 `reference-0.4.20-web2`。Core 来源版本从锁定的源码基准核验，避免仅更改界面版本字样。
- 新 DTO 承载楼层身份/标高、真实参数类型及单位、重叠证据、规划设置、资料来源/hash、布尔迁移预条件、导出计划。关键内容全部进入规范化 hash 与签名。
- 旧协议的检查与写入计划不能直接复用。旧草稿保留，重新扫描后明确显示可复用、冲突及失效目标；已有 0、否、空白与人工面积按当前核心语义处理。
- 发布时保留旧客户端的账号读取及六文件更新入口；旧业务请求返回明确的升级提示，不假装接受协议 2 字段。切换和回退须覆盖仍在运行的旧客户端及已签发许可的期限，不能在校验错误时继续写模型。
- 快照检查覆盖异步期间的文档切换、模型/类型变化、资料变动与共享参数绑定。事务失败整体回滚，写后回读及全面复检；未提交资料阻止导出。
- 外部平台同步使用独立启动授权，绑定 Web 账号、平台项目/目标模型、冻结 IFC hash、run ID 和组件版本；不套用仅 30 秒的 Revit 属性写入许可。已启动长任务不因普通登录续期失败被强杀。

## 独立组件与升级

- 在既有 DLL 中嵌入主包对应的组件锁定信息；不能依赖旧更新器会丢弃的 package.json 新字段或不会提取的根目录 descriptor。
- 锁定 Node 25.4.0 Windows x64 和由 Local 0.2.0 适配出的 Web 同步组件 `0.2.0-web.1`；发布前验证来源、哈希及真实 CLI 运行。客户端使用随包运行时，不替换系统全局 Node。
- zetta 提供按版本保留的签名组件清单及归档。签名使用独立域，绑定主包/源码、组件 ID/版本、OS/架构、协议、大小和 SHA256；使用已有安装公钥及正常 HTTPS，同源下载并拒绝重定向。
- 组件包与主包分别执行大小约束；组件解压还限制总大小、条目数、路径穿越、重复路径和链接。客户端不运行 npm install 或包内安装脚本。
- 使用 Web 独立、不可变的组件版本目录，校验完再原子发布；下载失败保留已有属性管理、账号和草稿，给出可重试状态。新装验收以全部所需组件就绪为完成。
- 同步任务记录组件版本；旧 worker、未决写入及报告任务引用的版本继续保留。组件准备不迁移活跃 SQLite，不自动开始或重放历史任务。
- 检测 Edge 可用性；缺失时显示明确的环境缺项。Web 平台账号与内网 Web 账号是两套身份，凭据在用户电脑通过 DPAPI 保存。

## 交付顺序

1. 锁定 Local 0.4.20 源码清单、安装及模型保护基线；完成共享源码同步。
2. 建立协议 2 与服务端规则、资料和整轮规划计算；补旧版拒绝、草稿迁移与签名回归。
3. 接齐客户端取数、设置、编辑、资料事务及完整 IFC 导出；界面参照 Local 当前实际效果。
4. 接入独立运行组件、Web 平台同步与报告流程，验证旧客户端升级与新机安装。
5. 在模型副本完成实机体验检查，形成候选包；更新 zetta，回下载验证，核对运行版本与本地/远程分支一致。

每项完成均需形成可复现证据，整体交付以全部流程贯通为准。

## 验收清单

- 核心当前 267、资料表 21、红线 33、同步 80 等已有用例在对应运行时全部执行；Web 新协议、授权、编辑、签名和升级另做针对性回归。现有数字是 Local 历史基线，不能写成这轮已通过。
- 对真实模型副本走完全面检查→设置/资料→人工编辑→预览→写入→回读→复检→保存重开；覆盖人工面积、0/否/空值、布尔迁移、多选混合状态和未选构件保护。
- 实际原生 IFC 导出后独立核验属性类型、值、实体/属性集归属、面积、源模型恢复、命名和最终目录；导出完成与平台审查通过分别记录。
- 核对实际显示的主窗口、设置、导入冲突、导出和同步窗口；沿用 Local 样式，按钮必须有可完成的动作。
- 使用真实旧六文件更新器安装新版主包，随后自动获取锁定组件；同时验证首次手动安装、坏签名/错版本/中断、离线已有组件、并发准备和旧 worker 仍运行。
- 测试资料、模型副本及新 Web 状态与 Local 隔离；对受保护 Local 安装和原 RVT 做前后哈希核对。
- 平台端至少验证登录、读取、绑定、预览、状态恢复及已有冻结报告读取。真实模型替换/计算需用户在届时预览中明确确认具体项目和目标模型，并以当时可编辑状态为前提；历史成功任务不得自动重放。
- 端到端平台写入仅在上述条件具备时进行；条件不足时明确列为未完成的验收项，不能用本地夹具代称正式平台验收。Local 现有跨电脑并发边界也不能因迁移而宣称已解决。
