# HIFC 报规—总图模型标准化

目标是让现有报规总图模型的业务分类、参数和导出载体符合当前插件契约。保留模型整体形状、位置和有效业务信息；按下述规则拆分不相交载体、补建缺失停车 Area。优先结合图像和模型推断，保留判断依据。

## 系列与适用范围

| 技能方向 | 范围与状态 |
|---|---|
| 报规—总图 | 当前技能，处理总图中的用地、道路、绿地、停车区域等对象；实际验证范围和限制见适配说明。 |
| 报规—单栋地上建筑 | 后续独立技能，负责单栋地上建筑；识别、映射和检查规则待对应模型实验。 |
| 报规—地下建筑 | 后续独立技能，负责地下建筑；识别、映射和检查规则待对应模型实验。 |

三类分别维护识别依据、类目映射和检查规则，可共用证据记录、副本写入与复检原则。本技能的总图实验结论不得外推为地上建筑、地下建筑或施工图阶段的规则；另外两类尚未建立，不预设其必需构件或字段。现有调用名保留为 `$hifc-model-standardize`。

## 开始时

读取用户指定的模型、当前加载的插件版本和契约。常用项目为 `D:\18_建模项目\湖北BIM云平台\V1`，以实际存在的文件及宿主加载的 DLL 为准。适配方法见 [references/v1-adapter.md](references/v1-adapter.md)。

确认阶段为报规、处理范围为总图；用户已明确的信息直接沿用，无需重复询问。结合图像、实际构件和空间关系判断模型用途并保留证据。混合模型仅处理可明确归属总图的对象，不将建筑对象套用总图规则；纯地上建筑、地下建筑或施工图模型应转入对应技能范围，并说明当前技能未覆盖。

实验默认使用独立副本。记录原文件与复制文件 SHA-256、原文档路径、ProjectInformation.UniqueId、当前未保存状态。原文档未保存时使用磁盘版本，并对比当前关键参数，说明差异；不要为取副本擅自 SaveAs 当前文档。避免切换用户当前视图或干扰其他开发任务。

## 盘点和判断

每轮重新枚举完整模型，包含 Area、房间、楼层、项目、链接状态；排除材质、贴图和非模型资源。先取轻量清单，再对相关对象提取几何。已有类目或通用“构件类型”不等于业务分类完成。

每个候选保留：

- 当前文档标识、ElementId、UniqueId、族/类型、类别、实例/类型参数来源。
- 拟映射类目、可支持的 IFC 实体、字段、旧值、新值、单位。
- 证据来源、判断理由，以及已确认/可可靠推导/待确认状态。

ElementId 和 UniqueId 仅用于本项目定位与防误写，禁止把旧案例 ID 作为跨项目识别规则。

先导出并阅读可辨认的总平面、面积平面和三维图像，将图中的红线、道路、建筑轮廓、车位排列与真实模型对象对应；再综合原生参数、几何和空间关系判断。视图因远端 CAD 对象而缩成一点时，在副本中临时裁剪或隔离并重新导出，不能拿不可读截图当作已看图。实际尺寸参数优先于类型名称中的数字。

没有其他资料时，主动通过读图和模型形成合理推断，标明依据与置信程度，在已授权副本中验证，不把可以自己分析的问题逐一交给用户。只有图像、模型及上下文仍无法区分且会实质影响结果的事项，才集中提问。图示与参数冲突时保留冲突事实，优先核查。

停车区域从 Area 的真实闭合边界与停车实例关系识别。按面积方案和所属标高区分重叠 Area。插入点、包围框或数量只能作为证据；结合图像中的连续车位组判断归属，记录边界交叉、孔洞、错层、重复和链接坐标问题。依据完整车位组推断的数量与严格落在旧 Area 内的数量分开说明。

若没有对应 Area，按用户授权自动创建承载停车信息的 Area：按同标高、空间连续性和实际车位轮廓分组，推断合理边界，创建正确面积方案下的面积平面/边界/Area，再写分类。边界基于车位组，不把整块道路、绿地或空白场地一并圈入。复杂或有遮挡的组先补读局部图像。优先复用已有 Area，禁止重复；既有泛称 Area 可标准命名为“停车位_<标高>_<两位序号>”。新建后校验面积非零、边界闭合、组内车位覆盖及没有重叠重复。

## 绿地和道路的构件连通性

绿地、道路不允许一个 Revit 构件包含多个不相交几何体：每个独立几何体必须有自己的构件身份。每轮全面检查都要验证这一项，不能因分类已填写而跳过。

按模型空间中的真实连通体判断。先合并同一构件实际相交的实体，再检查分离体；一个 Solid 也可能包含多个分离体。轮廓环数不等于连通体数，外轮廓里的孔洞必须保留，不能将孔洞填实或单独建成构件。几何读取、布尔运算失败时明确记录未验证，不用包围框或三角片数量代替连通性结论。

在授权副本中拆分时，保留原生线段和圆弧、类型、标高、偏移、阶段及有效业务属性。核查外部标注、宿主、组、连接和草图约束等依赖，禁止无声丢失。先创建新构件、验证几何，再移除旧载体；在同一事务组内完成，失败回滚。记录旧 UniqueId/ElementId 到新对象的映射，为子构件设置唯一标记，不为区分实例而制造多余类型。

拆后分别重新计算面积及其他几何派生值，不能把旧构件总面积复制到每个新构件。验证每个构件恰有一个连通体、原有孔洞和曲线保留、几何并集一致、总面积与体积守恒、没有重叠或重复；重新调用插件全量扫描并保存重开复核。曲线积分面积、Revit 面积读数和插件三角网投影面积分别记录，同一算法前后比较并注明容差。实施细节见 [references/v1-adapter.md](references/v1-adapter.md)。

## 填值与预览

生成可定位的映射预览。可靠几何量按契约转换单位；名称、标高等原生信息可以直接引用并标明来源。默认值须有明确规则或用户授权，并在预览中标作默认值。

当前约定只有道路宽度必须手填。其他字段优先结合图像与模型推导并注明依据；仍未知时解释原因，不擅自新增必填限制。不将空值补为 0、否。公建车位、充电等运营或设备属性需要对应证据。室外停车及层数可结合建筑外轮廓、三维位置、普通/机械停车形式推断，不能只靠一个标高名称或 Area 对象数量。

既有值与建议冲突时展示差异。分类切换只清理旧类目专属实例值，保留共用值和同类型其他实例所需数据。未经确认的业务含义保留待确认；可以继续执行已确定的部分。

用户已授权本轮副本实验、基于读图推断和缺失停车 Area 自动补建时直接执行该范围。需要创建新的设计对象或更改原文件时，先完成可审阅的预览，再确认超出本轮授权的部分。

## 写入和验收

优先调用已加载插件的预览、写入和复检方法，以相同规则验证兼容性。写入前核对路径、文档标识、对象 UniqueId、插件与契约版本、原值和参数定义。固定 GUID 用于新建共享参数；已有同名参数的 GUID、绑定、单位和只读状态需分别核对。

确定性写入在目标副本文档的事务组中执行，回读失败整体回滚。不得对正在使用的原文档试写。参数名称存在但只读或有多个同名来源时报告冲突。

完成后：重新全面扫描、逐项回读、核对几何和实例数量、保存副本、关闭并重新打开，再次读取。重复运行应不产生重复分类、参数或无意义写入。

导出验证必须核对实际 IFC 中的实体、Pset、值和所有者。Area 在插件内显示为 IfcSpace 不保证它真的进入 IFC。分别报告：模型写入、插件读取、保存重开、IFC 导出、正式平台验收。没有平台回执就不能声称报规通过。

## 工具和交付

- `scripts/capture_model.cs`：通过 Revit MCP 执行的只读取数正文。参数为目标已打开文档的绝对路径、输出目录、阶段、模型类型。输出完整插件扫描及相关几何；不会打开、保存或修改模型。
- `scripts/spatial_evidence.py`：读取 inventory.json，对闭合 Area 与停车包围框做空间核对。用 `--deps` 指定兼容 Python 版本的 Shapely 路径。输出仅为证据，不写模型，不决定车位数。
- `scripts/ApiWork.cs`：小型 ExternalEvent 执行桥，供本轮生成的确定性写入、保存重开或视图恢复代码使用；编译与调用见适配说明。每次执行写独立回执，不把排队视为完成。
- 大模型按相关对象增量采集几何；当前脚本的几何范围为楼板、Area 和停车实例。其他载体需要补充取证，不能因脚本未覆盖就宣布缺模型。

交付技能入口、标准化副本、简明可视化报告及机器可读预览/回执。报告列出实际成功写入、保留待确认、缺失或导出阻塞，不用“全绿”替代事实。
