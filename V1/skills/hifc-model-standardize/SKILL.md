# HIFC 自动标准化报规

交付是一份已另存、已实际写入属性、可继续人工编辑和导出的标准化 RVT。遵循用户当前确认及真实插件契约；每轮全面检查，复用未变化的有效数据。当前流程为：**最新模型 → 规范另存为 → 全面检查与预览 → 插件写入 → 保存重开回读 → 按请求导出与独立核验**。

## 范围与按需读取

| 本轮工作 | 读取内容 |
|---|---|
| 命名、另存、恢复既有成果、Revit API 与导出 | [V1 适配说明](references/v1-adapter.md) |
| 总图：用地、控制红线、道路、绿地、停车与连通性 | [总图规则](references/site-rules.md) |
| 单体：用途、楼层、人工面积、投影面积及地下区域 | [单体规则](references/building-rules.md) |
| Excel、布尔迁移、来源冲突、红线人工资料、验证层级 | [数据与验收](references/data-and-validation.md) |

阶段须人工确认；同一任务已确认的直接沿用，不由模板的“施工图”文字推翻报规决定。模型类型综合真实构件、空间关系和已确认用途判断，文件名只提供线索；混合模型按对应业务处理。仅有负标高不证明有地下建筑。地上地下可归属于同一个建筑，无需为本技能拆成两个文件。

本技能处理模型，排除材质、贴图和非模型资源。参考案例与平台规则只约束适用对象，不要求项目具备字典中的全部类目。

## 1. 先另存标准化文件

确认来源路径、最新保存状态、当前未保存修改、ProjectInformation.UniqueId 及实际加载插件版本/哈希。对已有源文件记录磁盘 SHA-256。以用户本轮最新模型内容为源，**在业务写入前通过 Revit 另存为独立标准化 RVT**；原文件磁盘内容保持。当前有未保存编辑时，应纳入另存成果；确实只能取得旧磁盘内容时先说明差异，不能将旧内容当作最新模型。

默认目标为来源同级文件夹，可用用户指定目录。统一命名：

`3D_项目名称_阶段_具体单体名称或总图_YYYYMMDD_V1.rvt`

例如：

- `3D_歇马镇中心学校_报规_综合楼_20261023_V1.rvt`
- `3D_歇马镇中心学校_报规_大门_20261023_V1.rvt`
- `3D_歇马镇中心学校_报规_总图_20261023_V1.rvt`

具体单体名称只出现一次，不附加泛称“单体”，成果文件名前缀固定为 `3D_`，不含“标准化”字样。原始输入的 `3D_` 可有可无；复杂旧文件名通过已知项目资料明确拆分，不把日期识别为楼栋。新一轮成果使用同目录、同项目/阶段/模型/日期的最大版本号加一，避免覆盖旧成果。用户指定继续某份符合现规则的标准化成果时直接复用并保存该份文件；要求新一轮交付时再另存新版本。旧“标准化_”前缀只作读取兼容，新成果另存为 `3D_`。

用 `python scripts/standardized_name.py --help` 查看命名工具。它只输出路径及身份计划，不创建 RVT；正式 SaveAs 前再次核对目标未存在。解析到标准化名称也不代表该模型已完成写入或验收。

## 2. 全面检查，复用已确认数据

每次重新枚举完整项目，包括项目、楼层、Area、房间、模型实例和链接状态；界面筛选、预选及旧检查完成标记不缩小范围。已有类目或泛用“构件类型”不证明业务已完整。

保留对象 UniqueId/ElementId、实例/类型、字段定义/GUID、旧值、拟写值、单位、证据及确认状态。ID 只用于本模型定位，不作为跨项目规则。参数身份以插件定义及实际来源核对，不能只看同名文字或其他软件的显示值。

先读取已有业务参数和插件持久资料，再比较本轮对象、几何、分类和来源变化。有效且未变化的人工值、已确认类目与证据直接复用；只对新增、变化、缺失及冲突项继续分析。每轮仍做全量确定性检查，但无需让模型重新推理整套已确认信息。几何/楼层/来源改变后重新计算受影响建议，旧预览和旧分摊失效。

在需要判断用途时读取清晰总平面、面积平面或三维图，并对应实际对象。无法从模型与现有资料可靠区分且影响结果的事项集中询问；继续处理已确定部分。模型缺失与取数脚本未覆盖须分开报告。

## 3. 预览并通过插件持久写入

按“用户本轮明确修正 → 当前有效人工值 → 经选择采用的资料值 → 有依据的自动建议”处理；来源相冲突时展示旧/新值。共用值只补空；批量覆盖须有本轮明确范围。未经确认的量值不补 0，已明确的布尔默认另按规则执行。

- 2026-10-23 技能发布审查时用户再次确认：当前 HBBIM 报规标准化**将适用单体的“民用建筑”统一写为“否”**，已有“是”纳入明确修正预览，经插件实际写入，记为当前平台兼容操作规则。这是最新用户要求，不将其解释为已通过单变量实验证明的分类因果；建筑用途名称仍按实际用途填写，人防参与独立处理。后续更具体的用户指令优先。
- 建筑用途名称缺失，以及“区内道路类型＝消防道路”的道路宽度缺失，要在对应类目/属性明确标红。其他道路不套用手填宽度要求。草稿不解除缺失，实际写入并复检后再解除。
- 布尔空值默认“否”；空的建筑基底优先按已确认基底楼层，未确认时首层默认“是”、其余“否”。已有明确值（包括首层人工“否”）保留；编号和数值 0/1 不据此变成布尔。
- 人工楼层面积、相关区域分摊值、建筑投影面积及其他已确认业务值均实际写入 RVT。仅在导出时临时映射正确，仍不足以交付标准化成果。

使用已加载插件的全面预览/批量写入/回读链。项目和楼层属性使用全面管理路径，不能套用仅允许所选实例的快捷写入。类目切换清理旧类目专属实例值，保留共用与共享类型数据，再补新类目对应值。出现只读、同名歧义、迁移依赖或过期预览时报告原因，事务失败回滚。

确认的业务字段保存在 RVT 项目、楼层、构件或适用类型参数中。阶段、确认与来源资料复用插件支持的模型存储/暂存；旁路回执只补充追溯信息，不能成为业务值的唯一载体。后续打开标准化 RVT，即使没有本轮临时脚本，也应能查看、修改和导出已写属性。

## 4. 保存、重开与交付

完成写入后全面复检、逐项回读，保存标准化 RVT，关闭重开后再次读取。正常重复执行应无重复参数、对象或无意义写入。旧值被用户在 Revit 改动后，以本轮真实读取和当前规则重新核对。

需要 IFC 时，默认导出当前项目全部可导出模型，包括有效 Area 与未分类几何；不要求预选、不因未赋业务属性排除普通新增模型，链接源文档不自动并入。先处理未写草稿与阻塞；采用完整成功回执并核验导出回滚，不以文件存在判断成功。实际 IFC 检查实体、属性集、值、单位、实例/类型归属与几何；用真实 GUID 建立映射。

交付标准化 RVT 的可点击路径、命名版本、已写属性概况、人工待补/冲突项及验证层级。按需附 IFC；正常交付目录只生成 IFC，机器可读回执保存在插件内部或本轮内部证据目录，记录来源/成果哈希、插件/规则版本、写入与保存重开结果。不要给用户交付目录附加日志和配置，除非用户另行要求。区分模型写入、保存重开、IFC 核验、平台计算成功和法规审查结果；平台无本轮回执时不宣称已通过。

## 可复用工具

- `python scripts/standardized_name.py`：只读命名、身份解析与版本计划，避免重复名称和标准化后缀干扰导出命名。
- `scripts/capture_model.cs`：通过 Revit MCP 采集已打开目标模型的全量插件快照及相关几何，写取证文件，不保存/修改 RVT。几何采集仅覆盖楼板、Area、停车等既有范围；单体其他对象按需补采。
- `python scripts/spatial_evidence.py`：闭合 Area 与停车实例空间证据；结果不自动决定车位数。
- `scripts/ApiWork.cs`：需干净 Revit API 上下文时使用的 ExternalEvent 桥；执行结果以独立回执为准。调用细节及适用能力见 V1 适配说明。
