# 来源、资料与验收

## 业务值、定义和单位

当前模型中真实有效值优先复用；用户本轮明确修正（包括 2026-10-23 再次确认的适用单体“民用建筑＝否”标准化规则）列为有依据的变更。批量共用值只补空，资料与模型冲突需展示并选择；业务结果实际写进 RVT，回执不能替代参数。

核对字段 GUID、来源、实例/类型绑定、类型/单位、可写性与同名歧义。固定 GUID 和共享参数定义复用插件，不另造一套。窗共享类型等修改须核对整组影响，避免所选实例赋值连带污染未分类对象。类型与实例业务 Pset 的出口分别验证。

以 m²/m 表达编辑和导入的面积/长度；原生参数按 Revit 内部单位换算，不能依据项目当前显示为毫米/平方英尺去猜。普通 Number、文字和编号不做面积/长度缩放。人工面积和几何差异记为两种口径，而非自动回退到模型测量。

## 布尔和旧参数迁移

插件与 Revit 属性使用 YesNo 复选框，实际 IFC 为 IfcBoolean。空布尔按否；空基底按已确认基底层（未确认时首层）默认是，其他层否；已有明确人工值保留。识别基于字段定义，不能把编号 0/1 转为布尔。

旧文字布尔交由插件整批预览和迁移，保留所有绑定类别及实例/类型值；先核查明细表、过滤器、全局参数、族/外部来源与非法值，失败连同写入回滚。存在合法旧值但尚未迁移时，不能把它当作空白默认否。

同名不同类型的字段不能共享一个定义。当前插件为总平布尔“建筑密度”与场地数值、楼梯段布尔“间距/退让审查”与保温层文字使用独立来源别名，IFC 字段名维持契约。使用插件已有别名/迁移政策，禁止手工删除旧定义完成迁移。

## Excel：一栋一份明确资料

使用插件报规表导入，按当前工作表与目标楼栋建立对应。支持一栋一工作表或文件；混合表中的“综合楼/大门”及“6455.60/37.6”不自动拆配。源表空白不清模型值，冲突默认不选，已确认选项进入原有草稿后实际写入。

保留文件哈希、工作表、单元格、原始/未映射资料与选用结果，使用插件已有 RVT 资料存储并与属性同事务提交；原始单元格不会自动成为官方 IFC 字段。只导入资料也需写入和保存。未写的资料/属性草稿均须处理后再导出。

楼层面积导入走同一人工楼层—区域联动，不覆盖未选用的人工值。建筑密度、容积率、绿地率与面积比例不一致时展示核对，不擅自改成另一统计口径；不是所有 Excel 单元格都新增为插件必填。

## 人工红线坐标

当前先收集用户人工填写的模板；保留表头、原数值和来源。坐标单位、X/Y 方向、内部/共享坐标对应关系未明确时只能记录“资料已收集/尚不能比对”。不能从同一模型自动生成所谓权威点后再与自己比较。

框架已确认后，通过实际变换将模型轮廓和资料点置于共同坐标空间，核查水平位置、轮廓、闭合、点序和偏差；坐标来源的真实测绘/审批有效性单独说明。当前自动实体比较仅覆盖单水平直线棱柱、单外环；曲线、多环/孔洞等未支持形态报待核对。

真实平台坐标上传、服务器红线审查需对应授权和执行证据；本技能的本地资料保存和几何比对不等于已提交平台。

## 验证层级与成功条件

| 层级 | 必须有的证据 |
|---|---|
| 已预览 | 当前对象身份、实际旧值、建议与来源、冲突清单；不计为写入 |
| 已写入 | 插件事务完成，按实际参数回读值/类型/归属；排队与创建空参数不算 |
| 已保存 | 标准化 RVT Save 成功，关闭重开后值和业务身份一致 |
| 已导出 | 完整导出服务成功，恢复/回滚检查完成，实际 IFC 哈希及逐项独立核验 |
| 平台计算成功 | 对应本轮 IFC/模型的任务、时间和结果；历史“已完成”不替代 |
| 法规审查结果 | 本轮实际输入、命中规则和审查结果；空列表/无对应规则不算通过 |

原生几何检查至少包含业务载体数量、身份、属性归属、楼层/建筑关系、世界位置及 Body 可解析；schema 正确不等于几何正确。曲线积分、Revit 面积、网格近似分开记录，不能通过放宽阈值掩盖缺陷。已知不同算法小偏差不能直接断言是平台失败根因。

排查平台异常时，固定成功基线及文件哈希，每轮只变一个字段或明确相关的一组面积；核对非目标属性、几何和层级不变，记录上传/计算结果。平台默认值、规则选项、参考软件输出与用户确认均保留各自来源，不从一个成功案例推导所有字段都正确。

当前平台将非工业项目归入“商住”入口，用户已说明此项不是学校项目问题。学校绿地、停车数量、具体面积、屋面及 0.5m 调整都留在项目确认记录，不提升成全局默认。当前“民用建筑＝否”是用户于 2026-10-23 再次确认采用的兼容操作要求；历史单字段用途中学的实验因果记录保留，不互相覆盖。

## 当前能力边界及证据入口

2026-10-23 的 `V1/docs/revit-property-data.md` 和 `V1/validation/0.4.17-preview.2-validation.json` 记录：生成模型 36 项原生检查、实际 IFC 40 项独立核验通过，另有 38 项刻意未填来源，完整业务审计仍未通过。客户真实项目迁移、坐标服务器审查和正式平台验收不能据此宣布完成。

0.4.18 已实现分类可编辑下拉，并完成生成模型原生 38 项和 IFC 独立 48 项检查；0.4.19 候选完成导出命名与单文件交付的原生 26 项和 IFC 27 项检查。0.4.19 正式化仅改版本元数据、重新构建和安装，正式新哈希尚未重复宿主验证。见主线 [0.4.19 交接](https://github.com/ArchitectureWorld/BIM-baogui/blob/v0.4.19/V1/docs/HANDOFF-0.4.19.md)；不同轮次的数字不可相加冒充整套客户项目验收。技能所写操作意图不能代替实际宿主支持。启动任务先核对加载版本、参数契约和字段能力，按证据报告不支持项。已有有效成果可直接继续使用，无需为了核对能力反复重装或重启宿主。
