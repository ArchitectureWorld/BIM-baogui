完整规则进一步确认：250 不在总平构件合法枚举内；雨篷 Pset 拼字不一致、室内停车场缺定义、窗的标高/底高度被运行时策略排除。现有案例规则与实际项目规则不能混为同一检查标准。下述是已实现功能和历史实测状态，新发现尚未写入生产代码。

## 本轮变化

延续“1 阶段 → 2 模型类型 → 3 全面检查 → 4 写入 Revit”。新增“计算设置”，包含：

- **计算范围**：集中列出普通楼板的建筑区域候选、用地红线的净用地候选，可定位选中对象。名称不足以判定用途时由人确认；同投影的两块净用地不得同时确认并写入。
- **项目共用值**：一次设置建筑类型、类别、用途及建筑区域功能和系数等，只补空值。已有值继续在右侧属性中单独编辑。不复制平台模板默认值，不要求所有空字段手填。
- **实际楼层**：默认取已确认建筑区域的所属楼层，也可手动选实际楼层、最高层上边界。地坪、地下楼层和基底仍在“楼层 / 基底 / 基准”确认。
- **本轮计算核对**：明确显示未确认范围、缺失输入、尚未写入的建议值和面积差异。检查对象、源值、建议值与平台实际计算分开记录。

设置按项目暂存，重开仍完整扫描。未写入的分类确认绑定 UniqueId、名称、类型、楼层及当前投影；几何变化或对象替换后需重新核对，不靠旧数字 ID 套用规则。

## 有来源的自动值

- 建筑模型识别支持“墙 + 楼板 + 标高”的组合，不再只依赖独立门窗；不因此把所有楼板自动定为建筑区域。
- 平面顶面采用 Revit 原生面面积乘法向投影，保留曲线和孔洞；非平面表面检查两档细分的收敛情况，不能可靠计算时报告缺口。
- 实际楼层可生成项目计算标高、到下一确认楼层的层高及本层已确认区域投影面积。没有上边界时，不凭空填顶层高度。
- 建筑面积按完整确认范围内“区域投影面积 × 计算系数”汇总；未确认范围、缺系数、几何缺失或同层区域重叠时，不用部分值冒充整栋总面积。
- 地上层数按实际楼层及确认地坪确定，不因模型中存在未使用的 -1F 标高就增加地下建筑。
- 既有值（包括 0 和否）保留；面积与本轮模型不同会提示。单次写入中暂存的系数修改参与该次新增汇总建议，原扫描不被修改。

只有道路宽度继续要求手填并使用对应类目标红；计算缺口不构成新增强制手填规则。材质不参与检查。

**完整规则审阅后的限定：** 建筑技术“建筑面积”、楼层“计算标高/楼层面积”、建筑技术“地下建筑高度”未出现在这份 420626 / SUBTYPE=0 模板中，属于本地辅助结果，不能作为该平台必需输入。现有 `PlanningInputs.Issues` 尚需据此调整，不能用这些指标替代真正的功能、系数和建筑技术业务字段。

## 导出候选策略

继续原生 `Document.Export`、全项目输出及事务回滚，不后处理 IFC。候选导出采用 IFC4 Design Transfer View 和高细分设置，以避开 Revit 2020 Reference View 曲线折线化路径中已观察到的短边与闭合问题。

首轮实际导出证明所有 Body 可读（建筑 4661、总图 26），包括旧失败对象 613491、720177。但两个多块几何楼板 660521、717044 各生成两个 IfcSlab，并重复整块投影面积；另有 6 块总图楼板精细网格面积与 Revit 原生投影相差超过 0.001㎡。因此首轮候选未通过几何和计量验证。

后续候选在既有原生 Exporter 扩展中，对 IfcSlab 楼板调用 Autodesk 随 Revit 2020 提供的通用楼板入口；接口缺失、载体数量异常或任一楼板失败时拒绝成功。新副本已确认单体 8 块楼板对应 8 个业务实体，包含完整多块几何和孔洞，原重复计量已消除。类型 Pset 仍按案例继承输出，建筑区域业务 Pset 挂实例；类型路由与 250 的平台兼容问题仍未解决。

本轮已定位 250 来自原 Revit 类型的文本参数；非空即业务证据及“有类目的楼板都追加总平 Pset”两处策略过宽。修正需按真实业务类目决定输出，不迁移或替换错误值，不清除用户原始类型参数。

冻结契约不改；建筑技术“建筑面积”的原始 `Reall` 仅在该字段运行时映射为 `Real`，与原有地下层数拼写兼容同样独立核验。
