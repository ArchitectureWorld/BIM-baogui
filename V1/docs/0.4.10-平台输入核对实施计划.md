# 0.4.10 平台输入核对实施计划

**目标：** 按用户本轮确认，消防道路宽度单独要求手填；明确平台默认值影响，补充批量输入和导出前核对；保留人工面积优先并验证实际 IFC。

**依据：** `网页相关报告/ifc-regulation-audit-20261021.html`、已验证 0.4.9 面积规则及本轮用户指令。使用 writing-plans、test-driven-development 和 executing-plans，在当前 V1 中连续执行。

**架构：** 核心层统一产生按构件和字段定位的输入核对项；管理窗口、导出核对窗口与导出回执共用该规则。原生导出仍使用既有面积同步和临时事务回滚。Revit 2020 / .NET Framework 4.8。

## 约束

- 仅 `Pset_道路边界线信息属性集 / 区内道路类型=消防道路` 的道路宽度强制手填；不把所有道路或红线宽度设为强制手填。
- 平台默认值仅用于说明风险，不写成模型事实。零、否、人工清空和缺失分别处理。
- 本轮开发不补写学校原始 RVT，不改交付的单变量 IFC，不自动猜绿地类别、道路等级或配建系数。
- 人工楼层面积优先；已有区域面积、模型几何和系数按 0.4.9 规则处理。窗口未写入草稿必须在导出前明确处理。
- 源码、测试、包和安装状态分别记录；本轮不自动提交或推送 Git。

## 重点回归

1. 普通道路改成消防道路再改回，红色手填提示随实际用途更新。
2. 红线宽度虽允许为空，仍显示平台 15m 默认影响；未选择地区规则不虚构默认。
3. 公建车位“否”是明确值，批量统一设置只补空；主/子功能按真实父项校验。
4. 预览显示的面积必须与最终临时物化值一致，原模型及用户草稿不被导出改写。
5. 点击取消、定位对象、保存后重开和重复检查均保持原有数据；无规则及缺输入不能展示成平台通过。
