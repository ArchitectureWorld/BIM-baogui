> 后续真实项目验证发现：0.2.0 的自动扫描被文档对象引用身份校验错误阻断。0.2.1 已修正并编译，待安装和宿主回归；此前原生服务测试不代表此窗口链路通过。最新情况以 `validation/management-development-status.json` 为准。

新主入口：**H-IFC V1 → 模型属性管理 → 模型检查 / 属性管理**。窗口打开会自动扫描当前项目，不需要先在 Revit 中选中构件。主窗口可与 Revit 同时操作。

## 使用流程

1. 打开项目后点击主入口，等待扫描完成；扫描有进度并可取消。
2. 点击“必要模型范围”，勾选本次项目必须存在的业务要素并应用。未勾选项作为本次不适用；未确认范围时不会显示整体通过。
3. 从总览指标、左侧模型树或必要模型清单查看缺口；按楼栋、楼层、类目、名称或 ID 筛选。
4. 在管理清单内选择构件，或使用“选取筛选范围”批量操作。双击构件或点击“定位所选构件”在 Revit 中查看。
5. 对未分类或缺参数构件，在右侧选择业务类目，点击“预览分类与参数准备”。预览列出类目修改以及拟新增的原映射参数；确认后执行并自动复检。
6. 对已有实例属性，在右侧选择属性、填写新值，点击“预览属性修改”。核对旧值、新值和目标构件，再执行写入并复检。
7. 不参与本次检查的候选构件可“移出核验”；可查看排除项并恢复。这只调整本次检查范围，不删除或修改模型。
8. 本次数据检查通过后，可从窗口导出当前核验范围。实际 IFC 核验与原软件同模型 A/B 仍需单独执行。

## 看懂完成情况

| 指标/状态 | 含义 |
|---|---|
| 必要模型 | 按本次已确认清单统计已识别业务要素；不是把全部 43 类自动设为必需 |
| 待分类 | 要素尚未识别，但存在可能匹配的未分类候选，不直接判定模型不存在 |
| 未识别到 | 必要要素没有已分类模型，也没有适配的未分类候选，需要检查建模缺口 |
| 载体待支持 | 本版尚未实现该 IFC 载体的扫描/编辑，不伪装为通过或物理缺失 |
| 类目确认 | 本次核验范围内已确认类目的构件数 / 候选构件数 |
| 映射字段有效填写 | 已确认类目的有效来源字段 / 该范围的映射字段；尚未分类不按 100% 处理 |
| 缺参数 / 未填写 | 参数不存在 / 参数存在但未赋值，分别显示；0 与 false 保持有效 |
| 值非法 / 有歧义 | 类型不符或同名来源不唯一，需要处理后复检 |
| 本次数据检查通过 | 适用清单已确认、必要模型存在、范围内类目和来源字段完整；不等同于几何业务合规或平台验收 |

## 范围与记录

当前支持楼板、墙、屋顶、门窗、房间、常规模型和楼梯段的参数扫描；链接模型未纳入可写范围。项目/楼栋/楼层等未适配载体明确显示待支持。未提供楼栋或楼层归属时显示未指定，不推测分组。

扫描在 Revit 允许的上下文分批读取身份和相关参数，不进行全量几何捕获。取消、模型变化和项目切换会使结果需复检。预览后参数变化会拒绝写入；事务写入并回读，不允许留下部分失败的修改。

类型来源属性本版只读，避免批量改类型影响范围外实例。新参数的类别绑定可能影响其他同类别构件，因此若会产生族/类型同名冲突会阻断并提示统一来源。长度/面积等实例数值按项目单位解析；已有文本来源仍保持参考映射的原值语义。

原始 `Reall`、`Integerl` 等仍标为类型待核验，未自动纠正。必要模型清单来自项目确认，官方补齐继续延后。

检测和修改记录保存在 V1 的 `outputs/`；检查范围配置在 `outputs/management-profiles/`，不写入用户 RVT。0.1.0 包与历史实测证据保留。
