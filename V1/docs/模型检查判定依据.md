# 模型与属性检查的判定依据

适用当前版本 **0.4.4 / Revit 2020**，更新于 **2026-10-19**。当前验证范围见 [0.4.4 验证摘要](../validation/0.4.4-validation.json)。

用户已确认先用三份通过 HIFC 的报规 IFC 作为案例参考，官方内容以后补充。插件先要求人工确认阶段，再识别或人工指定模型类型，随后选择对应案例清单。案例基线保持冻结，不将冻结映射中的全部 280 条配置自动视为必填。

## 对照范围

| 阶段与类型 | 本轮参考 | 边界 |
|---|---|---|
| 报规 / 总图 | 七个实例业务集及总平构件类型集，共八类 | 来源为成功总图案例；不照搬构件数量和数值 |
| 报规 / 单体建筑 | 申报、建筑技术、建筑楼层、建筑区域、总平构件，共五类 | 两个单体共同存在的集合 |
| 报规 / 单体建筑补充 | 窗类型集 | 只在厂房案例观察到，不一律判缺窗 |
| 报规 / 总图及单体补充 | 人防区域、消防分区、停车场和停车位 | 使用 Area → IfcSpace，按项目实际适用，不新增必要构件 |
| 施工图 | 基础模型盘点 | 没有施工图案例规则，不套用报规通过标准 |
| 类型不明或混合 | 给出识别证据，等待人工选择本轮类型 | 不依据文件名或任意猜测套用清单 |

详细来源见 [成功案例分析](成功案例01-Pset与构件基线分析.md) 及 `reference/success-case-01/case-profiles.json`。基线清单的哈希为 `2118bcea847210f562a6b40d286fae71517db9b087639f0025f658cf31e700e2`。基线清单里的历史集成状态是提取时记录；当前集成与验证状态见 [0.4.4 验证摘要](../validation/0.4.4-validation.json)，地下区域的依据和边界见 [专项说明](0.4.4-报规地下区域与指标.md)。

## 结果如何理解

- “参考项未找到”：本轮既没有确认载体，也没有候选对象，需要检查模型或分类；不直接断言物理模型不存在。
- “待确认分类”：发现候选对象，但业务含义需核对。场地、道路、绿化等组合可用于识别总图；单独名为“道路”不会直接决定道路业务分类。成功案例的 UniqueId 对应及当前名称/类型/类别复核，可以给出具体道路分类的有据预览。别名证据和载体矛盾单独保留，详见 [0.3.2 识别依据](Revit2020-0.3.2-成功案例构件识别.md)。
- “缺参数”和“未填写”分开；成功案例允许空值的字段单独标记。0、false、空值保持区分。
- 参数存在率表示案例字段是否存在；有效属性值比例表示映射类型检查通过的字段比例；二者均不是合规率。类型字段按实际类型载体去重。
- 建筑信息适配到 Revit 项目信息，楼层信息适配到标高，对应 IfcBuilding 与 IfcBuildingStorey。0.4.4 已在受控地下副本核验相关指标和空间归属；该结果仅覆盖本轮字段与载体。
- 目前仅道路宽度要求手填，未填时对应类目标红。其他空值仍展示状态并允许编辑，不增加强制手填项。
- 多候选、同名定义冲突、实例/类型绑定冲突、非法值和未覆盖链接单独报告。

## 只检查模型

材质、材质资源、贴图、渲染、图例、相机、内部草图以及管段规格定义不进入模型清单，不赋 HIFC 参数，也不影响完成度。实际模型构件、模型边界、项目和楼层信息仍纳入。普通构件没有当前案例专用属性集时保留盘点，不强制赋予一个专用业务类目。

## 每次全面检查

每次重新枚举当前文档，读取当前实例、类型与属性，不用上次已完成状态跳过对象。用户删除重建、改类型、清空或手工覆盖属性后，旧结果和预览失效；重新检查必须发现这些变化。界面搜索和筛选只改变显示，不改变全量检查范围。

在右侧属性中查看、修改自动建议和草稿，点击“4 写入 Revit”后，按文档、检查编号、模型变化序号、载体身份与旧值校验后写入；回读失败回滚，正常写入后自动全量复检。自动值来自当前模型的名称、标高与实际几何面积等可核对来源，不使用案例数值替代本项目数据。地下层数、高度和地坪标高须先人工确认“地下楼层 / 基准”，已有手工值保留并提示差异。

“选中构件赋属性”用于非标准模型的人工分类和实例属性写入，限定所选范围；完成后仍全面复检。人防、消防及停车四类报规区域使用 Area，房间等其他 IfcSpace 来源需要核对载体，不能仅凭 IFC 实体类型自动分类。地下建筑区域继续使用楼板。

官方合规性、完整几何/指标业务校验、全部 HIFC 类目和客户真实地下项目的正式平台验收仍待补充。本轮原生 IFC 的多类区域、建筑指标与类型/单位核验见 [0.4.4 专项说明](0.4.4-报规地下区域与指标.md)。官方补充按用户要求延后。

历史上，2026-10-15 的 0.3.2 在三个模型副本验证了候选、预览证据、写入与全面复检，当时停车位仍待核对，见 [0.3.2 实机记录](../validation/workflow-20261015-123730/验证结论.md)。后续版本已接入 Area 并完成原生 IFC 核验，不能将历史待处理状态作为当前结果。测试通过不表示本项目 HIFC 业务值已填齐或已获平台验收。
