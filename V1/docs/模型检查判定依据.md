# 模型与属性检查的判定依据

适用当前正式版本 **0.4.19 / Revit 2020**，更新于 **2026-10-23**。当前验证范围见 [正式验证摘要](../validation/0.4.19-validation.json) 和 [开发交接](HANDOFF-0.4.19.md)；下文按版本保留历史依据。

0.4.17～0.4.19 增加布尔复选框与受控迁移、报规表导入、红线资料、可编辑分类下拉、命名确认及单 IFC 交付。自定义文字分类允许写入/导出，但平台认知需另验；并非修改原始冻结字典。

2026-10-23 用户在技能审查中再次明确：当前 HBBIM 标准化作业将适用单体“民用建筑”统一写为“否”，已有“是”列入明确修正预览。此为最新操作口径；0.4.12 用途单字段实验的因果结论仍保留，人防参与独立处理。正式插件继续保护已有明确值，技能经批量预览/写入执行该规则，本次发布不增加隐藏覆盖。

0.4.15 根据用户明确确认：已归为“规划控制线”，且原生名称、类型或两项业务字段明确对应“用地红线／净用地规划控制红线／净用地控制红线”的载体，名称和红线类型必须统一为“净用地控制红线”。检查及分类生成规则建议，写入时修正空白或旧默认值；原值保留到事务成功，清空及错误标签被拒绝。其他控制线不套用，不据此将规划净用地面积载体重新分类。依据是本项目确认规则，未改写官方冻结快照。

0.4.12 新增已验证口径：用户确认在综合楼 IFC 上仅补入“建筑用途名称＝中学”即可避免住宅分类和居住区法规匹配，两份对照的“民用建筑”均为否。程序在当前平台方案的有效选项中增加“中学”，冻结快照的裙房／塔楼仍原样保留；不扩展其他枚举，也不把中学自动套入其他项目。建筑用途名称缺失时左侧类目及右侧属性标红，草稿不算完成，每次全面检查重新读取，写入并复检后解除。人防参与单独设置，民用建筑不参与本次分类修复。

0.4.11 补充面积边界：已分类区域的有效已填面积合计与楼层已填值一致时，不需要重新分摊，未分类候选继续提示核对但不误拦导出；需要分摊或已确认区域投影重叠时仍保留拦截。

0.4.10 按用户本轮更正：仅“区内道路类型＝消防道路”的道路宽度需要手填。下文较早版本中的“道路宽度”范围表述作为历史保留，道路宽度以本条为当前口径；建筑用途名称的新增要求见 0.4.12。平台默认值仅解释缺项后果，不写成模型事实；用户导出入口显示实际面积取值并阻止未写入草稿被忽略。综合楼与总图副本已完成本轮实机核验，54 项独立检查通过；这不等同于新一轮平台审查通过。详见 [本轮说明](0.4.10-消防道路与导出核对.md)。

0.4.9 固化用户已确认通过平台计算的面积规则：已有有效楼层面积优先，按本层已确认区域的原面积比例同步区域投影面积。预览、统一写入和全项目导出使用同一规则；区域不齐全、重叠或分摊依据已改变时报告原因，几何与系数不随之调整。详见 [面积同步说明](0.4.9-人工楼层面积同步.md)。

0.4.8 可按项目选择保康县 420626 / SUBTYPE=0 / 报规规则快照。显示必填仅用于适用类目的计算核对，不等于要求项目包含全部类目或逐项人工填写。只将道路宽度列为强制手填；不抄平台默认值制造完整。总平构件需明确分类，普通类型文本不构成业务依据；实际楼层与辅助标高分开处理。详见 [本轮说明](0.4.8-平台规则与验证状态.md)。

0.4.7 增加普通楼板、用地红线和道路的待确认候选，以及项目共用值和实际楼层计算。候选不等于已分类；统一设置只补空值。同投影净用地不得重复计量，建筑面积只汇总完整确认且可测、无已发现重叠的区域。仅道路宽度强制手填，平台计算缺口不增加人工必填项。详细方法及当时的待核验边界见 [0.4.7 说明](0.4.7-计算输入与验证状态.md)。

用户已确认先用案例 01 的三份报规 IFC 及案例 02 的两份单体 IFC 作为原案例参考基线；0.4.8 已补充保康县 420626 报规规则快照，其他地区、其他阶段及尚未覆盖的官方内容仍待补充。案例 02 虽有“施工图”模板文字，用户明确仍为报规。插件先要求人工确认阶段，再识别或人工指定模型类型，随后按所选配置核对规则。案例基线保持冻结，不将冻结映射中的全部 280 条配置自动视为必填。

## 结果如何理解

- “参考项未找到”：本轮既没有确认载体，也没有候选对象，需要检查模型或分类；不直接断言物理模型不存在。
- “待确认分类”：发现候选对象，但业务含义需核对。场地、道路、绿化等组合可用于识别总图；单独名为“道路”不会直接决定道路业务分类。成功案例的 UniqueId 对应及当前名称/类型/类别复核，可以给出具体道路分类的有据预览。别名证据和载体矛盾单独保留，详见 [0.3.2 识别依据](Revit2020-0.3.2-成功案例构件识别.md)。
- 墙、窗的业务分类仅以人工分类或专用业务证据为依据；普通名称、类别和原生尺寸不构成专用业务分类或候选的依据。
- “缺参数”和“未填写”分开；成功案例允许空值的字段单独标记。0、false、空值保持区分。
- 参数存在率表示案例字段是否存在；有效属性值比例表示映射类型检查通过的字段比例；二者均不是合规率。类型字段按实际类型载体去重。
- 建筑信息适配到 Revit 项目信息，楼层信息适配到标高，对应 IfcBuilding 与 IfcBuildingStorey。0.4.4 已在受控地下副本核验相关指标和空间归属；该结果仅覆盖本轮字段与载体。
- 案例 02 的地上地下各属于同一栋建筑，实测保留一个 IfcBuilding；不据此强制所有项目拆分地上、地下文件。室外地坪等标高可能没有原生 IFC 楼层载体，须与真正建筑楼层分开解释，不能把扫描记录数直接当 IFC 楼层数。
- 0.4.8 总平构件按明确分类的实例输出专属属性。窗人工分类不修改共享宽高；原案例模式的窗类型属性只挂在类型上，Pset 宽高按案例的 Revit 英尺原值保留。选择 420626 报规配置后，窗标高、底高度和宽高按实例字段及平台单位处理；几何尺寸另按 IFC 单位独立核验。
- “建筑用途名称”缺失或值无效时对应类目与属性标红，需按实际用途确认并写入；已保存值保持。另仅“区内道路类型＝消防道路”的道路宽度要求手填。其他空值仍展示状态并允许编辑，不扩大手填范围。
- 多候选、同名定义冲突、实例/类型绑定冲突、非法值和未覆盖链接单独报告。

## 只检查模型

报规总图的绿化楼板在载体匹配、没有人工类目及冲突候选时，默认生成绿地补齐项；其他载体不据此自动分类。楼板可人工指定为规划控制线，导出事务临时转换为 IfcBuildingElementProxy 并使用 NOTDEFINED，结束后回滚；改回绿地恢复 IfcSlab 并清理旧控制线专属值。

材质、材质资源、贴图、渲染、图例、相机、内部草图以及管段规格定义不进入模型清单，不赋 HIFC 参数，也不影响完成度。实际模型构件、模型边界、项目和楼层信息仍纳入。普通构件没有当前案例专用属性集时保留盘点，不强制赋予一个专用业务类目。

## 每次全面检查

正式 IFC 导出默认使用当前项目全文档原生范围，包含 Area 和未分类模型，不使用预选、管理窗口筛选或当前视图来缩小范围。无效 Area 和未覆盖映射单独报告；已有空属性保留为空，不以导出成功替代属性完整度检查。详见 [0.4.5 导出与验证](0.4.5-绿化默认分类与规划控制线.md)。

每次重新枚举当前文档，读取当前实例、类型与属性，不用上次已完成状态跳过对象。用户删除重建、改类型、清空或手工覆盖属性后，旧结果和预览失效；重新检查必须发现这些变化。界面搜索和筛选只改变显示，不改变全量检查范围。

在右侧属性中查看、修改自动建议和草稿，点击“4 写入 Revit”后，按文档、检查编号、模型变化序号、载体身份与旧值校验后写入；回读失败回滚，正常写入后自动全量复检。自动值来自当前模型的名称、标高与实际几何面积等可核对来源，不使用案例数值替代本项目数据。几何测量不等于申报面积口径；原有零面积仍保留。

在“楼层 / 基底 / 基准”中确认实际地下楼层、地坪基准和基底楼层，确认记录按模型暂存，楼层删除 / 替换后失效。地下指标及建筑基底只补空值，已有手工值和“否”保留并提示差异；基底不必是首层，例如案例 02 的 1# 基底为 -2F。

“选中构件赋属性”用于非标准模型的人工分类和实例属性写入，限定所选范围；完成后仍全面复检。人防、消防及停车四类报规区域使用 Area，非空专用业务参数优先于面积方案名称，多个专用证据冲突仍待人工确认。房间等其他 IfcSpace 来源需要核对载体，不能仅凭 IFC 实体类型自动分类。地下建筑区域继续使用楼板。

0.4.6 已在客户实际单体副本中核验类型挂载、Area、楼层归属及指定几何尺寸，原始模型保持只读。2# 建筑编号的源值与参考 IFC 不同、公建车位源空值、室外地坪无 IFC 楼层等差异单列，严格完整度没有改成通过。本次已接入 420626 报规规则快照，其他地区、其他阶段及尚未覆盖的官方业务口径和类目仍待补充。正式平台上传、解析和服务器计算验收仍待完成。

历史上，2026-10-15 的 0.3.2 在三个模型副本验证了候选、预览证据、写入与全面复检，当时停车位仍待核对，见 [0.3.2 实机记录](../validation/workflow-20261015-123730/验证结论.md)。后续版本已接入 Area 并完成原生 IFC 核验，不能将历史待处理状态作为当前结果。测试通过不表示本项目 HIFC 业务值已填齐或已获平台验收。
