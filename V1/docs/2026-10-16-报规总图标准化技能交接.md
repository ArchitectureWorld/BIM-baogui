## 用户已明确的工作约定

1. 阶段由人工确认；已经明确的信息沿用。模型用途结合实际对象和图像判断。缺少外部资料时，主动读图并结合模型推断，保留依据、置信程度和冲突事实。
2. 每轮重新全面扫描模型；不能只检查历史目标清单或认为已有分类就无需再查。只处理模型及业务属性。
3. 当前只有道路宽度必须手填。其他字段优先读取或可靠推导；未知值保留并说明原因，不擅自增加必填限制，不将未知写成 0 或否。
4. 停车位应有对应的原生 Area。缺失时，在已授权副本中按同标高、连续车位组和真实轮廓推断边界，创建面积平面、闭合边界及 Area，标准命名为 `停车位_<标高>_<两位序号>`；已有可用 Area 优先复用。
5. 绿地、道路每个不相交几何体必须对应一个独立 Revit 构件。按真实连通体判断，保留孔洞和原生曲线；拆后分别重算派生值，不能把原总面积复制到每块。
6. 默认在独立副本实验，写入前检查文档身份、对象 UniqueId、实际插件构建、参数定义和原值；事务、回读和失败回滚形成闭环。
7. 分别报告模型写入、插件读取、保存重开、IFC 实体与属性、正式平台验收。没有平台回执就不能称为报规通过。

## 技能资源与使用

| 文件 | 用途与限制 |
|---|---|
| `SKILL.md` | 范围、证据判断、停车 Area、绿地/道路连通性、写入与交付流程。 |
| `agents/openai.yaml` | 展示名称、简述及默认调用提示。 |
| `references/v1-adapter.md` | Revit 2020 / H-IFC V1 接口适配、ExternalEvent、几何核验及已验证范围。 |
| `scripts/capture_model.cs` | Revit MCP 只读取数正文；读取插件完整扫描，并补充楼板、Area、停车等相关证据。其他载体需补充取证。 |
| `scripts/spatial_evidence.py` | 用 Area 边界与停车实例包围框做空间核对，输出证据；不会决定业务车位数或写模型。 |
| `scripts/ApiWork.cs` | ExternalEvent 执行桥。具体写入正文按当前副本生成，读取执行回执后才能判断完成。 |

调用示例：使用 `$hifc-model-standardize` 分析指定报规总图，在独立副本中结合总平面与三维图像完成分类、属性和几何载体标准化，并提交可定位报告与验证回执。

`capture_model.cs` 的四个参数依次为：目标已打开文档的绝对路径、输出目录、阶段、模型类型。阶段和类型值须从当前插件确认。`spatial_evidence.py` 接收 `inventory.json`，可通过 `--deps` 指定与 Python 版本匹配的 Shapely 路径，通过 `--out` 指定输出文件。不要因脚本只提取部分载体的几何，就判断其他业务对象不存在。

本机安装副本与本分支的六个技能文件保持内容一致，仓库副本统一文本换行。后续修改应同步安装副本与版本化目录；另外两类技能成熟前保持总图边界。

## 实验结果与限制

实验对象为黄冈营养膳食中心报规总图。以下为已保存回执的整理，本次提交没有重新启动 Revit 或执行模型修改。

| 项目 | 证据与结论 |
|---|---|
| 用地与道路用途 | 用户确认“用地面积_100”为规划净用地，“车行道路_100”按道路边界线映射；这些确认仅适用于本项目。 |
| 初次标准化 | 用地、道路、绿地、停车 Area 分类及属性实际写入；保存重开回读一致；重复分类没有新增变更。 |
| 停车缺失分支 | 可按连续车位组补建闭合 Area，插件识别为停车位；该分支通过回滚测试。交付副本复用已有 Area，没有制造重复对象。 |
| 绿地拆分 | 原构件 393385 含 10 个分离体，重建为 10 个原生楼板，每个恰有 1 个连通体。 |
| 道路连通性 | 道路 393030 为 1 个连续实体，保持 1 个构件及其孔洞。 |
| 绿地属性 | 每块独立重算投影面积，写入值合计 1491.053028㎡。原生曲线、整体几何及保存重开核验通过；新绿地之间没有重叠。 |
| 原生面积差异 | 曲线积分、Revit 面积读数、插件三角网投影不是同一算法。回执分别保留数值与误差，不能混用作为守恒判断。 |
| 绿地 IFC | 10 个独立对象及各自面积属性通过；IfcOpenShell 仅解析出 9 块几何，第 05 块 396482 失败。拆前对应挤出体也失败，此问题仍未解决。 |
| 原有接触 | 第 06 块绿地与道路已有约 0.000011112m³ 微小交叠，拆前拆后一致；第 05 块贴边处原生布尔求交不能量化。不能宣称道路与绿地全部零交叠。 |
| 停车边界 | 19 个连续停车族实例支持数量推断，但原 Area 边界切过末端车位，边界仍待复核；不能等同为 19 个车位均完整位于现有 Area 内。 |
| 正式报规 | 未取得正式平台验收回执。 |

新绿地 IDs 为 `396445, 396454, 396462, 396470, 396482, 396490, 396499, 396506, 396514, 396522`，实例标记为 `绿地_室外地坪_01` 至 `_10`，保留类型 `绿地_100`。这些 ID 仅用于本案例回溯，禁止作为跨项目识别规则。
