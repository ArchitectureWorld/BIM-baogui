# 0.3.1 · 阶段、模型类型与全面检查

用户已确认的流程：人工确认报规 / 施工图阶段 → 自动识别或人工指定模型类型 → 根据阶段及类型选择参考清单 → 全面检查并生成补齐预览 → 批量写入及全面复检 → 缺失报告。

## 使用

进入 `H-IFC V1 → 模型属性管理 → 模型检查 / 属性管理`。窗口保持独立，可以与 Revit 同时操作。

1. 人工选择阶段；模型类型可选“自动识别”“总图”“单体建筑”。阶段不自动推断。修改阶段或类型会使旧结果、旧预览失效。
2. 点击“全面检查并补齐属性”。窗口分批读取当前文档的模型对象、项目信息、标高及关联类型。自动识别的依据显示在窗口顶部；混合或证据不足的模型需要人工指定本轮类型。
3. 左侧显示本阶段 / 类型的案例清单；顶部区分参考项覆盖、字段存在和有效属性值。中间可以搜索、筛选、定位对象，筛选不改变全量检查范围。
4. 扫描完成后自动生成整批补齐预览，无需选择 Revit 构件或逐项选择待补对象。预览列出新旧值、属性载体以及类型修改影响的实例数量。确定后点击“写入已预览项并全面复检”。
5. 存在多种分类候选、参数定义冲突、非法值或缺失业务值时，在清单和“人工处理”页查看。通过清单选择对象，修正分类或填写属性；仍经过预览、事务回读与全面复检。
6. 每次成功完成的全面检查自动保存 JSON 和 HTML 报告到 `outputs/<本轮目录>/`；也可通过“保存检查与缺失报告”另存完整报告。

## 依据与写入原则

- 报规依据为 `reference/success-case-01/case-profiles.json`，使用嵌入资源和哈希核对。总图七类业务实例集加一类通用类型集；单体共同五项，窗为案例补充项。载体数量不照搬案例。
- 建筑的申报 / 建筑技术信息集中读取 Revit 项目信息；楼层信息从标高读取。这是当前管理适配，不等于这些数据的实际 IFC 导出已完成验证。
- 实例业务集与类型附加集共同展示；同一类型的字段计数去重。普通模型对象保留盘点结果，不强制全部归为 HIFC 专用类目。
- 用户明确限定只管模型：材质、材质资源、贴图、渲染、图例、内部草图及相机等辅助定义不进入模型清单，也不影响检查完成度。实际模型构件、模型边界、项目信息、标高及链接覆盖情况仍纳入。
- 只准备案例观察到的来源字段，不把冻结配置中所有字段当作必填。成功案例中观察到的空值单列允许；空值与缺参数、0、false 区分。
- 自动补值目前限于语义明确的 Revit 原生文本（标高名称、已填写的建筑名称）和确认的业务分类；不复制成功案例的面积、数量、标高、坐标或业务代码。数值 / 单位口径待参考软件同模型验证。
- 新共享参数按固定来源 GUID 创建。实例 / 类型绑定或同名定义有冲突时报告，不能覆盖。类型属性修改在预览中显示同类型影响范围。

## 全量与失效规则

每轮重新枚举当前文档，不沿用旧的构件 ID 清单或“已完成”状态，旧版排除项不再参与扫描或统计。当前视图和界面筛选不决定扫描范围。

扫描期间模型变化、取消、文档切换、预览后任何文档修改都会使结果失效。写入前复核文档身份、检查编号、模型变化序号、载体 UniqueId、参数来源及原值；写后回读，失败回滚。正常写入后重新执行完整扫描。

链接模型列为未覆盖，要求在其源文档单独全面检查。施工图目前只提供基础盘点，规则待建立，不出具报规式通过结果。未纳入当前案例的已声明业务类目列为待补依据，避免误称不适用。
