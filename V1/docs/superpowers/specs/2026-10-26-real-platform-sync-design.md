# 真实平台单模型同步设计

## 已确认目标

2026-10-26，用户要求测试自动上传；核对 0.4.19 的真实适配器仍为只读后，用户选择“补齐真实自动上传程序，再用大门实测”。本轮实现学校项目大门的单模型闭环：完整成功导出、核对模型绑定、备份旧 IFC、网页上传替换、等待转换与计算、核验结果。运行时不依赖 LLM。

本设计落实已确认方案及既有 `网页相关报告/HBBIM_IFC_Automation_Handoff_v1.0.md`。公共前端脚本和旧报告仅为契约发现线索，不能代替本轮网络与页面实证。

## 方案取舍

- 用户选择：扩展现有 TypeScript/Playwright/SQLite 独立程序，与插件入口衔接，可重复执行并保留恢复记录。
- 未选：本次由会话工具代操作网页。它可以交付一次上传，但不能证明独立自动上传程序可用。
- 不采用后台写接口代替平台网页：必须让平台自身完成 IFC→FRAG 转换与自动计算。

## 边界

- 复用已安装的 Revit 2020 / 0.4.19 导出核心；只消费完整成功回执、冻结 IFC 及 SHA-256。
- 本轮仅学校大门模型，不操作总图、综合楼或其他已存在模型，不修改平台项目信息或提交报建/审查申请。
- RVT 原文件已按独立请求仅修改子功能为“大门”。用户已确认导出副本沿用主功能“学校”、用途“中学”、类别“中小学”、民用建筑“否”和面积 37.6㎡，子功能使用“大门”；原 RVT 不再改动。
- 账号入口用现有 DPAPI 加密文件；令牌不出现在配置、日志、命令行和仓库。
- 当前正式安装插件保持，候选构建通过后再考虑部署。不得触碰反编译目录。
- 用户随后确认项目仍审核中、不能替换。此次候选仅完成开发、本地验证、真实只读与文件准备；真实模型写入、计算提交及正式安装不执行。

## 真实适配器

新增显式 `real` 适配器，保留 `real-readonly` 和 `fixture` 的原边界。独立 Edge 持久目录，正常 TLS 验证，有界面运行。等待应用真正就绪，不能仅以 body 存在作为登录及项目读取成功。

项目识别同时使用可见表单及实测只读响应中的稳定字段；当前三维场景必须与编辑对象相同。以项目 ID、项目编号、项目名称核对，不以名称猜内部 ID。模型按唯一 ID、完整文件名及可核验代次绑定，代次使用本轮证实稳定的模型/文件元数据；缺证据时阻断，禁止生成伪 ID。

只读查询端点须从页面真实请求和返回值确认；允许经过证明的只读 POST，而非把所有 POST 都视为写入。网页选择文件、单模型删除确认及添加确认完成业务写入；不得调用私有 Vue 方法、改页面状态或伪造平台成功响应。

## 文件及恢复证据

删除之前取得真实旧 IFC 字节，验证 STEP/IFC 格式、模型归属、代次及 SHA-256，并持久保存。下载前后重新核对代次；没有可验证下载时不删除。新文件必须是冻结的完整成功 IFC，其命名保持用户批准规则。

写动作前持久化意图。真实平台不一定接受客户端操作 ID，因此适配器须保存本地动作证据，并以实际请求/响应、上传文件身份和当前模型清单关联。不能编造服务端幂等性。

响应未知时恢复只读核对：删除依据原模型是否消失及旁系模型是否变化；上传必须有与文件哈希关联的上传回执；提交必须能匹配已上传文件和新模型身份。证据不足保持 UNKNOWN_RESULT，不自动重复请求。

## 完成条件

平台成功必须同时成立：新模型唯一存在、旧目标消失、非目标模型集合和代次未变、冻结字节与新模型文件一致、当前模型转换成功、本次计算明确开始且完成或有等价的本次结果身份、活动预处理遮罩消失。历史“已完成”不算当前成功。

计算完成与法规通过独立展示。本轮不自动宣称法规通过。浏览器须保留至转换和计算完成；失败或超时保留证据和恢复状态。锁只保证本机排他，不能声称阻止异机用户并发。

## 插件界面

现有“平台设置 / 同步本次 IFC / 同步状态”继续使用。对真实适配器完成识别绑定后，允许显示具体替换计划并执行；状态窗口读取后台任务，不因 CLI 的两分钟 UI 等待上限中断正在进行的平台转换。原普通导出仍独立可用。

## 验证与交付

先用契约单元测试和本地仿真页面验证严格身份校验、上传响应关联、错误/未知状态恢复、旁系模型保护以及无令牌输出。再使用真实平台做只读连接和模型备份验证；最后只替换用户授权的大门，保留原远端 IFC 和完整证据。文档准确区分已测试部分与未达成部分，不以本地测试替代真实验收。
