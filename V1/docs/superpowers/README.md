# HIFC Local / Web 后续开发依据

本目录保存 2026-10-16 侧边讨论、主会话技术评估及后续补充。用户要求在独立 `hifc-web` 分支归档，便于以后开发。本次交付为设计文档，不代表网络版功能、Docker 或服务器已经部署。

1. [设计依据](specs/2026-10-16-hifc-local-web-design.md)：确认过的产品要求、安装决定、账号期限、数据保护范围和本地模型修改流程。
2. [实施计划](plans/2026-10-16-hifc-local-web-implementation.md)：文件和接口、实施顺序、验证步骤、部署、恢复与发包条件。
3. [计划编制时的环境快照](plans/2026-10-16-hifc-environment.json)：只读调查的原始结构化记录；资源和端口信息需要在实施前刷新。

## 已确定的范围

| 项目 | 决定 |
|---|---|
| 名称 | `HIFC-版本号-Local`、`HIFC-版本号-Web`；计划下一版为0.5.0 |
| 运行方式 | Local 在 Windows 本地执行；Web 在 Windows 保留 Revit 插件，由 Linux 计算规则和授权 |
| 服务器 | zetta-pc；安装官方 Docker Engine 与 Compose；业务容器为 HIFC、PostgreSQL、Caddy |
| 管理方式 | 当前 Windows 浏览器管理用户和期限；内部发包前加入 Portainer 运维面板；Windows 不需要 Docker |
| 账号 | 手机号＋真实姓名两项登记，只有管理员和普通用户两种角色 |
| 有效期 | 首次登记168小时；状态仅“有效 / 已到期”；管理员按任意正整数天数或指定日期延期 |
| 申请方式 | 同事通过既有渠道联系管理员，不增加试用、停用、套餐或审批流 |
| 模型写入 | 用户点“4 写入”，插件核验后在本地 Revit 事务中修改、回读、全面复检；RVT仍由用户正常保存 |
| 草稿 | 长时间编辑、断网、方案失效或账号到期均不清除人工草稿；再次写入前重新核对模型 |
| 数据保护 | Web 包及接口不交付完整规则库、案例库或私有引擎；用户能看到本次模型的字段和修改结果 |
| 业务范围 | 保留现有报规流程，只管模型和属性；施工图与缺失官方规则另行完善 |

## 本轮评估落实的调整

- 先验收 Local，再打通受认证的“采集 → Linux 检查 → Revit 写入、回读、复检”；完整后台和运维面板随后完善。
- 120秒方案和30秒许可约束开始写入的资格，不限制人工编辑时间；过期重新全检、合并无冲突草稿，有冲突展示三方值供确认。
- 合法开始的本机事务完整提交或回滚；“已写入”和“全面复检完成”分开报告，恢复联网不重复写入。
- 核心 DLL 嵌入资源、导出配置、隐藏入口和异常回退路径都纳入完整规则泄漏检查。

## 进入开发前需要完成

- 明确开发执行授权；当前要求只包含文档整理与分支同步。
- 对齐 main 后续已经验证的修复，更新代码和模型验收基线。环境调查基线为 `ecc768b491d38b60d9785c06f3bbd12f0237ba67` / 0.4.2；归档时main已提交0.4.3，本分支从 `cb34b20a80c172c5c24982e8a58be44c01464a4f` 建立，保留选中构件属性编辑与Area导出修正。
- 确认两字段登记后的自动设备凭证、DPAPI保存和换机绑定码方案。它是实现建议，登记规则已确定，认证实现尚待确认。
- 复核仓库可见性及下载权限。本次归档准备时 GitHub 仍返回 public，独立分支不会自动变成私有；完整部署记录须在适当的发布范围内上传。
- 按实施计划刷新机器、端口和工具情况。安装sudo秘密由用户在Windows终端交互输入，文档和仓库均不保存秘密。

## 分支与提交范围

`main` 保持稳定主线；`hifc-web` 用于本次文档和后续网络版开发，不形成 Local/Web 两套长期分叉的规则源码。本次仅提交本目录四份文档，不包含主会话未提交的代码、安装包、模型、凭据或运行日志。

后续按里程碑验收，再评估如何整合回 main。测试记录要区分自动测试、真实 Revit 副本、实际鼠标、原软件对照和官方平台验收，不将计划或历史记录当作新版已通过的证据。
