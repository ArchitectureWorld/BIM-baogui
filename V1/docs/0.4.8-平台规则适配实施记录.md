## 补测发现与修正

- 窗的“标高”在 Revit 中同时由两个内置参数暴露。仅当窗实例恰好具有这对参数、二者均指向实例所属的同一真实 Level 时归一读取，再按项目标高换算米值。自定义同名参数、不同引用仍保留歧义阻断。此前失败运行保留，不覆盖为成功。
- 独立 IFC 审计又检出共享窗类型继承错误：实例四个米值正确，但原生 `CreateElementTypeProperties` 忽略 schedule owner 检查，将同一实例描述再次用于类型，并按属性名回退读取类型宽高的英尺原值。平台实例窗现使用原生 `PropertySetEntryMap` 的 `UseCalculatorOnly`，只按桥接 GUID 读取已确认实例的物化值，拒绝类型及其它实例；不关闭普通 IFC 属性集，不改类型尺寸，不后加工 IFC。最终独立 IFC 75/75 通过，未分类同类型窗无直接或继承业务集，两扇窗的完整三角面、Overall 尺寸及其它 IFC 属性保持。
- 普通墙、幕墙及仅名称为“女儿墙”的对象不自动确认墙业务。已有人工类目，或非空专用字段“是否为女儿墙”仍支持识别；0/false 仍是有效原值，泛用“高度”和空参数绑定不构成证据。全项目几何收集不变。墙范围回归保留红、绿日志。
- 学校首轮保存重开核验先比指纹、后恢复规则配置，导致包含配置前缀的指纹不等；独立核对原值没有丢失。宿主现持久化确认配置，重开先恢复配置再核验原指纹，并记录逐目标输入。旧宿主 false 结果及补充数据核对证据均保留。
- 汇总只在单次调用内缓存每行候选，不跨扫描复用。同进程 5,205 行真实数据由 82.057 秒降到 4.205 秒；修改前后完整 Summary JSON 相同，输入未变。此对比只证明缓存优化不改变结果；墙识别的预期范围变化另有回归和新模型副本验证。详见 [性能核验](../validation/platform-0.4.8/performance/report.md)。
