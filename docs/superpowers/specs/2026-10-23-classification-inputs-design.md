# 分类下拉与自定义输入

用户已确认：管理窗口、手动工具及共用值界面统一使用可输入文字的下拉框；主功能到子功能按平台真实字典联动；未证实的建筑类别到功能关系不强行绑定。切换上级保留原子级值，提示不匹配；自定义分类按原文写入和导出，提示平台识别待验证。

复用已核对的保康县 420626、2026-10-20 平台快照。该字典有 11 类主功能，学校下有 23 项子功能；保留来源范围，不宣称全省通用，不改原快照。实际分类字段为建筑类型名称、建筑类别、建筑用途名称，以及各属性集已定义的主功能/子功能或公建大类/公建小类。

方案比较：仅完善管理窗口不能解决手动工具缺项；另建分类向导会重复现有草稿与写入流程。因此采用共享分类选项政策，加到现有三个编辑入口。布尔复选框、消防道路宽度、红线固定标签、数值类型和人工面积优先保持既有政策。未知自定义分类与其他严格枚举不混同。

默认可参考分类字典，不要求先切到平台规则配置；不因选项可用而自动改变模型规则方案。已填写的未列出值仍可见、可编辑；父级混合/缺失时不猜子级候选、不自动选第一项。自定义值能通过模型写入和 IFC 原值物化，但提示不能证明平台接受。不会自动设置民用建筑或项目用途。

在隔离工作区开发 0.4.18-preview.1，已安装 0.4.17-preview.2 保持可用。原模型和真实平台不作为开发写入对象。先验证核心导出取值与实际独立 WPF 交互，再安排受控宿主验证；不为开发中间过程打断用户试用。
