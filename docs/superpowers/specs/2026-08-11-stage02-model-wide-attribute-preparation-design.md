# Stage02 全模型构件属性准备 v1.1 设计

**状态：** 已确认，待实现

**确认日期：** 2026-08-11

**目标环境：** Revit 2020 + Rhino 8 + Rhino.Inside.Revit + Grasshopper 8

**规则包目标版本：** HBR-WUHAN-PLANNING / 1.1.0

**交付形态：** 单一 BIMBaoGui.Stage01.gha

## 1. 目标

Stage02 的核心职责是依据 H-IFC 要求，对 Revit 原生模型构件进行属性检查和准备，使其写入结果能够被 Stage03 以同一规则 identity、参数 GUID、数据类型和单位稳定读取。

新版 Stage02 从“用户先选择对象”调整为：

- 默认检查当前 RVT 的全部规则相关模型构件；
- 开启自定义范围后，只处理 Grasshopper 输入的 Revit 构件；
- 依据 H-IFC 角色、Revit 类别、族名称和类型名称自动决定构件应获得的属性；
- 先生成只读预览，再由用户显式确认写入；
- 参数定义按参数独立准备，字段值按构件原子写入；
- 允许整体部分成功，不因一个构件失败回滚全部模型。

Stage02 不导出 IFC。Stage03 继续负责全模型检测、导出门禁、IFC4 RAW 导出和 H-IFC 转译。

## 2. 权威规则层级

判定顺序固定为：

    H-IFC Entity / PropertySet / Property / 类型 / 单位
      -> H-IFC 模型角色及角色属性集合
      -> 允许承载该角色的 Revit 类别
      -> 经批准的族名称和类型名称
      -> 当前 Revit 构件
      -> Stage02 参数准备和写值

各层职责：

- H-IFC 决定某个模型角色需要什么属性；
- Revit 类别限定允许使用的技术载体；
- 族名称和类型名称识别实际构件属于哪个 H-IFC 角色；
- 实际 RVT 只提供候选名称，不能自行定义 H-IFC 语义；
- 无 H-IFC 依据或无法唯一确认角色的构件不得自动写入。

唯一可编辑业务源继续是：

    specs/hbr-rules/v1/source/hbr_rule_source.v1.json

不得新增第二份可编辑的名称映射表、CSV 或 GH 内部硬编码字典。

## 3. 规则包版本

冻结 Tag hbr-planning-mapping-v1.0.0 保持不变。

本增量继续修改同一个唯一规则源，并将包版本升级为 1.1.0。升级内容限于：

- 经 H-IFC 角色对照确认的 Revit 类别；
- 族名称别名；
- 类型名称别名；
- 名称匹配所需的结构和语义合同；
- 与上述内容对应的 manifest、生成物和测试。

以下 H-IFC identity 不得因本增量漂移：

- IFC Entity；
- PropertySet；
- Property；
- declared IFC type；
- canonical unit；
- propertyId；
- Revit 参数 GUID。

GHA 必须报告其嵌入的 packageId、packageVersion 和 SHA-256。1.1.0 完成验证后使用新的版本 Tag，不移动或覆盖 1.0.0 Tag。

## 4. 处理范围

### 4.1 默认全模型模式

自定义范围为 false 时，只扫描：

- 当前活动 RVT 文档；
- 唯一规则库涉及类别中的原生模型构件实例；
- H-IFC 角色允许的 Revit element kind。

明确排除：

- ProjectInformation；
- Revit ElementType；
- 标注和视图专用对象；
- 导入 CAD；
- Revit 链接模型中的对象；
- 唯一规则库未覆盖类别的对象。

ProjectInformation 继续由 Stage01 负责。Stage02 默认全模型模式只处理模型构件。

### 4.2 自定义范围模式

自定义范围为 true 时：

- 只处理“Revit 构件”端口输入的对象；
- 输入必须是 Rhino.Inside.Revit 运算器提供的强类型 Revit 构件；
- 不接受手工 ElementId；
- 不提供 Revit 交互点选；
- 空输入直接阻断，不能退回全模型；
- 输入对象必须属于当前 FileContext 对应的活动 RVT；
- 链接模型对象、类型对象和非模型对象直接拒绝。

输入构件在预览时冻结以下身份：

- Document fingerprint；
- UniqueId；
- ElementId；
- Revit 类别；
- element kind；
- 族名称；
- 类型名称。

### 4.3 范围冲突

自定义范围为 false，但“Revit 构件”端口存在数据时，Stage02 返回输入冲突并拒绝生成预览。它不得静默忽略输入，也不得根据是否有输入自动改变处理模式。

## 5. 新 GH 接口

### 5.1 输入

新版 Stage02 固定为 5 个输入：

| 顺序 | 输入 | 访问方式 | 行为 |
|---:|---|---|---|
| 1 | 文件上下文 | Item | Stage01 输出的强类型 HBR_FileContext |
| 2 | 自定义范围 | Item | 默认 false；false 为全模型，true 为输入构件 |
| 3 | Revit 构件 | List | 仅自定义范围使用的强类型 Revit 构件 |
| 4 | 生成预览 | Item | false 到 true 上升沿触发一次只读检查 |
| 5 | 确认写入 | Item | false 到 true 上升沿消费当前预览 |

删除旧输入：

- 元素Id；
- 角色提示；
- 交互点选；
- 项目信息。

Stage02 不再允许用户通过“角色提示”覆盖自动角色判定。

### 5.2 输出

新版 Stage02 固定为 8 个输出：

| 顺序 | 输出 | 内容 |
|---:|---|---|
| 1 | 预览 | 强类型、不可持久化的 Stage02 写入计划 |
| 2 | 构件明细 | 每个构件的身份、类别、族、类型、自动角色和处理状态 |
| 3 | 字段明细 | H-IFC identity、参数 GUID、现有值、建议值、来源和状态 |
| 4 | 阻断信息 | 名称不匹配、匹配歧义、参数冲突和输入错误 |
| 5 | 统计 | 扫描、匹配、无需处理、待写、成功和失败计数 |
| 6 | 失败报告 | 当前执行对应的 JSON 报告路径 |
| 7 | 规则身份 | packageId、packageVersion 和 SHA-256 |
| 8 | 总状态 | 当前阶段的稳定状态文本 |

## 6. 自动角色判定

### 6.1 名称规则来源

当前 1.0.0 规则中的 familyAliases 和 typeAliases 尚未形成完整实际模型名称库。1.1.0 实施前必须：

1. 从指定实际 RVT 生成候选类别、族名称和类型名称清单；
2. 将每个候选名称与 H-IFC 角色逐项对照；
3. 由人工确认其唯一角色；
4. 将批准结果写回唯一规则源；
5. 由 schema、语义测试和 manifest 防止漂移。

候选清单只是审查证据，不是第二份规则源。

### 6.2 名称规范化

匹配前只允许确定性规范化：

- Unicode 兼容规范化；
- 去除首尾空白；
- 连续空白归一；
- 大小写不敏感比较；
- 全角和半角等价归一。

不得自动删除业务标点，不得使用模糊包含、编辑距离、语言模型推断或未批准正则猜测角色。

### 6.3 判定顺序

每个构件按以下顺序判定：

1. FileContext 的模型类型和项目条件适用；
2. Revit 类别命中某个 H-IFC 角色的允许类别；
3. element kind 命中该角色的允许类型；
4. 族名称或类型名称命中该角色的批准别名；
5. 最终只得到一个角色。

结果分类：

- 类别不属于任何规则角色：NOT_APPLICABLE，跳过；
- 类别属于候选角色但名称未命中：NAME_NOT_MATCHED，业务阻断；
- 同时命中多个角色：NAME_AMBIGUOUS，业务阻断；
- 唯一命中：MATCHED，进入属性检查。

业务阻断构件不得写入。一个构件的名称阻断不阻止其他已唯一匹配构件进入预览和后续部分写入。

## 7. runtime 状态处理

Stage02 必须消费唯一规则库计算的 runtime decision：

- NOT_IMPLEMENTED：Stage03 对应 Owner 策略尚未实现；Stage02 不自动写入，标记运行能力未实现；
- UNCLASSIFIED_REQUIREMENT：允许准备参数和写值，但标记需求等级待定，不计入“Stage03 Strict 导出就绪”；
- SUPPORTED：正常准备和写入，并计入导出就绪；
- 未知或缺失状态：fail-closed，禁止写入。

runtimeStatus、runtimeBlockCode 和 runtimeBlockReason 必须进入构件/字段预览、稳定 hash、Data Tree 和卡片统计。

“写入成功”和“Stage03 Strict 导出就绪”是两个不同计数，不得混用。

## 8. 检查与预览

生成预览只读，不修改 Revit。

预览至少完成：

- 处理范围解析；
- 构件身份冻结；
- 自动角色判定；
- 条件与适用性判定；
- 参数 GUID、定义、类型和类别绑定检查；
- 当前值读取；
- 可靠值来源解析；
- runtime decision 投影；
- 待安装、待绑定、待写、无需修改、待填写和阻断分类；
- 稳定排序和 hash。

稳定排序至少使用：

    Document fingerprint
    -> UniqueId
    -> propertyId

全模型扫描不能在 Grasshopper 每次普通求解时自动执行，只能由“生成预览”上升沿触发。

## 9. 字段和值

角色唯一匹配后，Stage02 为该角色的适用字段准备 Revit 共享参数。

值处理原则：

- 有唯一规则批准的可靠来源时才生成写值操作；
- 可靠来源包括固定 GUID 当前值、规则批准的源参数或迁移别名；
- 没有可靠来源时仍可准备字段，但保持空值并标记待填写；
- 测试 fixture、示例表和 smoke IFC 中的样例值不得成为生产默认值；
- 不得使用模型名称推导业务属性值；
- 不得用空字符串覆盖已有非空值；
- 已有正确值标记无需修改。

必填等级待分类不等于可以伪造值。Stage03 继续依据 requirement 和字段状态执行导出门禁。

## 10. 两层写入事务

### 10.1 参数准备层

共享参数定义和类别绑定属于文档级操作。Stage02 按参数 GUID 去重，并为每个参数使用独立事务：

- 参数不存在时创建固定 GUID 的共享参数；
- 参数存在时核对名称、数据类型、实例/类型范围和可编辑性；
- 类别绑定不完整时只补充批准类别；
- 参数合同冲突时不得覆盖或创建近似替代参数；
- 一个参数失败，只阻断依赖该参数的字段和构件；
- 无关参数继续准备。

### 10.2 构件写值层

每个构件及其全部可写字段是最小原子单元：

- 每个构件使用独立 Revit 事务；
- 任一字段写入或回读失败，该构件事务回滚；
- 其他构件继续；
- 不允许同一构件出现部分字段提交；
- 整体结果允许全部成功、部分成功或失败。

重复执行必须幂等：

- 正确参数不重复创建；
- 正确类别绑定不重复修改；
- 正确值不重复写入；
- 上次失败、待写和待填写项重新检查；
- 已成功构件可变为无需修改。

## 11. 预览失效与确认复核

确认写入前分两级复核。

全局身份变化时整份预览失效：

- FileContext identity 变化；
- 活动 RVT 变化；
- Document fingerprint 变化；
- 规则包 packageId、version 或 hash 变化；
- 处理模式变化。

单个构件变化时只使该构件过期：

- UniqueId 无法解析；
- 类别、element kind、族名称或类型名称变化；
- 自动角色变化；
- 当前字段值相对预览变化；
- 参数合同相对预览变化。

过期构件标记 STALE_ELEMENT，不写入；其他仍与预览一致的构件可以继续。

## 12. 状态、统计与报告

总状态固定为：

- 等待上下文；
- 等待预览；
- 检查中；
- 预览就绪；
- 预览有阻断；
- 写入中；
- 全部成功；
- 部分成功；
- 写入失败；
- 结果过期。

卡片摘要至少显示：

    模式｜全模型 / 自定义
    扫描｜总数 N｜匹配 N｜无需处理 N｜阻断 N
    字段｜正确 N｜缺参数 N｜待写 N｜待填写 N
    运行｜未实现 N｜需求待定 N｜导出就绪 N
    写入｜成功构件 N｜失败 N｜未修改 N
    状态｜全部成功 / 部分成功 / 预览阻断

完整构件和字段明细进入 Data Tree。卡片只显示摘要和第一条稳定阻断。

失败报告必须：

- 绑定当前文档、规则包和执行身份；
- 列出参数准备结果和逐构件结果；
- 区分业务阻断、构件过期和技术失败；
- 不记录敏感堆栈或不必要的业务值；
- 在部分成功时仍生成可追溯报告；
- 不把部分成功写成全部成功。

## 13. 旧接口清理

新版 Stage02 使用新的组件 GUID。

旧 Stage02 直接删除，不保留：

- 旧组件类；
- 旧组件 GUID；
- 隐藏迁移组件；
- 端口迁移代码；
- 角色提示兼容；
- ElementId 或交互点选兼容；
- 项目信息兼容；
- 旧业务分支和旧接口合同测试。

旧 GH 文件中的旧 Stage02 将显示组件缺失，用户必须重新放置新版 Stage02。不得为避免该行为而复用旧 GUID，因为不兼容端口可能导致错误连线。

## 14. 自动化测试

### 14.1 规则库

- packageVersion 为 1.1.0；
- 1.0.0 Tag 不变；
- H-IFC identity、类型、单位、propertyId 和参数 GUID 不漂移；
- 类别、族别名和类型别名只能唯一命中角色；
- 未批准名称、模糊名称和歧义名称被拒绝；
- rulepack、fixture 和 manifest 可确定性重建。

### 14.2 范围与匹配

- 全模型只扫描当前文档的规则相关模型构件；
- ProjectInformation、类型、标注、视图对象、导入对象和链接对象被排除；
- 自定义模式只处理输入构件；
- 自定义空输入被阻断；
- 全模型模式存在构件输入时被阻断；
- 类别、element kind、族名称和类型名称按确定顺序匹配；
- NOT_APPLICABLE、NAME_NOT_MATCHED、NAME_AMBIGUOUS 和 MATCHED 分类稳定。

### 14.3 预览

- 生成预览不修改 Revit；
- 排序、canonical 内容和 hash 确定；
- fixture 样例值不会进入建议值；
- runtime 三字段进入 hash 和输出；
- 全局身份变化使整份预览失效；
- 单个构件变化只使该构件过期。

### 14.4 写入

- 参数按 GUID 去重并独立准备；
- 一个参数失败只影响依赖字段；
- 每个构件全部字段原子提交或回滚；
- 一个构件失败不影响其他构件；
- 部分成功统计和报告准确；
- 无可靠来源只创建字段、不写样例值；
- 重复执行幂等。

### 14.5 GH 合同

- 新组件恰好 5 个输入和 8 个输出；
- 新组件使用新 GUID；
- 旧组件、旧 GUID 和旧端口从生产代码及合同中删除；
- Data Tree 键、排序和转义稳定；
- 卡片模式、计数、部分成功和首个阻断显示正确。

## 15. Revit 实机验收

指定 RVT 必须完成：

1. 记录 RVT、GH、GHA 的 SHA-256 和代码提交 ID；
2. 默认全模型生成预览，核对扫描、匹配、无需处理和阻断清单；
3. 核对代表性类别的族名称、类型名称和 H-IFC 角色；
4. 确认写入并验证全部成功场景；
5. 制造一个构件写入失败，验证只有该构件回滚且整体为部分成功；
6. 保存、关闭、重开 RVT，验证参数和值持久；
7. 自定义范围输入多个 GH Revit 构件，验证只修改输入对象；
8. 自定义范围空输入，验证不会退回全模型；
9. 修改一个构件名称或值，验证只有该构件预览过期；
10. 重新执行，验证已完成构件无需修改，失败项可补写；
11. Stage03 以同一 GUID、类型和单位读取 Stage02 成功写入字段；
12. Stage02 成功写入的字段不得被 Stage03 报告为缺参数。

Stage03 能读取 Stage02 字段是本阶段的交接验收；它不等同于 Stage03 H-IFC 转译或外部检查器全链路验收。

## 16. 非目标

本增量不包括：

- 修改 H-IFC Entity、Pset、Property、类型或单位；
- 为未实现 Owner strategy 实现 Stage03 导出；
- 完成 359 条 requirement 的权威分类；
- 写入 fixture 或测试样例值；
- 支持 Revit 链接模型写入；
- 自动扫描或自动写入；
- 保留旧 Stage02 GH 接口；
- 将 Stage02 写入成功冒充 Stage03 全链路验收成功。

## 17. 完成标准

只有以下条件全部满足，Stage02 v1.1 才可声明完成：

1. 同一唯一规则源完成 1.1.0 名称映射升级；
2. H-IFC identity 和 1.0.0 Tag 无漂移；
3. 新 5 入 8 出 GH 组件取代旧组件且无兼容残余；
4. 默认全模型与自定义范围行为均符合本设计；
5. 自动角色判定只使用 H-IFC 依据和批准精确名称；
6. 参数级准备和构件级原子写值支持准确部分成功；
7. runtime 状态分级不被伪装为全部导出就绪；
8. 自动化测试、Release 构建和静态合同全部通过；
9. 指定 RVT 完成保存重开、部分成功、重试和自定义范围验收；
10. Stage03 能稳定读取 Stage02 成功写入的字段。
