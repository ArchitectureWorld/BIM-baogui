# 原生 Revit 总平报规全项扩展第一期设计

**状态：** 用户已确认，待书面审阅

**确认日期：** 2026-08-14

**目标环境：** Revit 2020 原生插件

**实施基线：** 已安装并完成现场写入试点的 v0.4.2

## 1. 目标

第一期将当前以绿地为代表的单项试点扩展为“总平模型全部适用报规项”的原生 Revit 工作流，覆盖：

- Stage01 项目初始化、登记信息、坐标和规划目标；
- Stage02A 构件与属性准备；
- Stage02B 项目实际指标录入；
- Stage03 对 Stage01、02A、02B 的统一检查、问题回溯和导出门禁。

“全部报规项”指当前总平模型检查清单列出的全部项目。第一期采用严格产品策略：清单项目不得由用户标记为“不适用”。这是一项产品门禁，不冒充尚未取得的官方检查器必填性结论。

第一期只覆盖总平模型。地上建筑单体、地下建筑单体等模型类型保留独立清单能力，但不进入本期交付范围。

## 2. 设计原则

1. 继续使用 Revit 原生插件，不新增 Web、Grasshopper 或外部常驻服务。
2. 字段以 `IFC Entity + PropertySet + Property + 类型 + 单位 + Owner/载体` 唯一识别，不能只按中文名称合并。
3. 规划目标与模型实际值保持不同身份，不能因为两者名称相同而写入同一字段。
4. 不伪造缺失数据，不以 `0`、空字符串或样例值代替真实值。
5. 写入成功、官方插件可识别、官方检查器通过是三个不同状态。
6. 批量执行允许部分成功；失败项不得回滚已成功且无依赖关系的对象或指标。
7. 每个错误必须说明缺什么、影响什么、去哪里补以及如何复查。

## 3. 权威规则与覆盖边界

现有基础规则源包含 359 个属性、14 个载体角色；v0.4.2 绿地扩展增加 4 个属性和 1 个角色，运行目录共 363 个属性、15 个角色。

第一期继续以唯一规则源及受控 overlay 生成运行目录，不创建第二份手工维护的字段清单。Stage03 的总平检查清单由以下内容生成：

1. Stage01 选定的模型类型；
2. 武汉通用报规规则基线；
3. 当前项目规划条件覆盖；
4. 当前版本已实现的字段、Owner 策略和载体证据。

规则源中尚未分类的 requirement 不能被描述成官方无条件必填。第一期严格模式只表示：凡进入本次总平清单的项目，均必须通过，且不允许人工标记不适用。

官方载体尚未证实的字段不得靠名称猜测。可以完成内部参数准备、写入和回读验证，但在 Golden RVT 经官方插件导出和检查器验证前，不得声明官方 H-IFC 闭环成功。

## 4. 三阶段职责

### 4.1 Stage01：报规条件和项目输入

Stage01 负责“要求是什么”和项目初始化事实：

- 模型类型；
- 项目身份和登记信息；
- 项目位置、坐标、标高、单位和坐标参照；
- 武汉通用规则版本；
- 项目规划条件覆盖；
- 规划目标值和限值。

Stage01 自己写入并回读其负责的项目输入，不处理构件语义和项目实际指标。

### 4.2 Stage02：数据生成和写入

Stage02 拆成两个独立原生 Revit 功能：

- `02A 构件与属性准备`；
- `02B 项目实际指标`。

两个功能使用同一规则身份、文档身份、结果协议和问题中心，但界面、输入和事务相互独立。

### 4.3 Stage03：统一检查和导出门禁

Stage03 同时检查 Stage01、02A 和 02B。它不补填、不首次生成业务值，也不修复参数；只执行完整性、格式、回读、时效性、跨阶段一致性和导出准备检查。

正常导出受红色阻断项限制。测试强制导出只用于当前开发测试，可以绕过业务缺项，但不能绕过导出器不可用、文档失效等技术错误，也不能把红色项目改成绿色。

## 5. Stage01 字段设计

### 5.1 项目登记信息

Stage01 录入、写入并回读：

- 建设性质；
- 建筑物编码；
- 现状名称；
- 审批名称；
- 详细地址；
- 不动产地址；
- 建成时间；
- 建筑状态；
- 建设性质代码。

`总建筑面积`虽然属于登记信息属性集，但第一期作为实际指标在 02B 手工录入，Stage01 只显示其来源和完成状态，不重复编辑。

### 5.2 项目位置与坐标

Stage01 管理：

- 经度、纬度；
- 项目基点坐标；
- 标高；
- 项目单位；
- 坐标参照。

优先读取 Revit 项目位置；允许用户修正。保存后必须从 Revit 回读确认，空值、无法转换或回读不一致均为阻断。

### 5.3 规划目标和限值

Stage01 管理：

- 建筑密度目标；
- 容积率目标；
- 绿地率目标；
- 建筑限高；
- 海拔限高；
- 机动车位要求；
- 非机动车车位要求；
- 配置套值；
- 非机动车类型；
- 非机动车折算系数。

这些字段必须明确标记为“规划目标/限值”，不得与 02B 实际指标混用。没有规划目标时保持空值，由 Stage03 按清单策略给出结果，不允许以实际值反填目标字段。

### 5.4 字段状态

Stage01 每个字段显示：

- 字段身份；
- 当前值和单位；
- 来源：人工录入、Revit 回读或 02B 引用；
- 是否属于当前总平清单；
- 写入和回读状态；
- 问题原因。

## 6. 02A 构件与属性准备

### 6.1 执行范围

02A 打开后先选择执行范围：

- **全模型扫描：** 扫描当前活动文档内规则相关的全部候选构件；
- **自主选择：** 使用 Revit 当前选择或交互点选，仅处理所选构件。

两种模式都记录文档指纹、规则版本、执行模式、构件 ElementId/UniqueId 和模型快照。

自主选择模式只处理构件语义和构件属性，不生成项目级汇总指标。

### 6.2 语义候选与确认

02A 根据批准的 Revit 类别、族、类型名称、已有参数和必要的几何特征生成语义候选，例如绿地、建筑基底、道路、停车场、规划边界和消防场地。

自动识别只产生候选，最终角色必须由用户确认。未确认、重复归类、冲突或无批准载体的构件进入问题中心，不得静默写入。

### 6.3 构件字段和值

02A 为已确认角色准备适用的构件级参数，读取已有可信参数和当前构件值，并在预览中显示现值、建议值、最终值及来源。

第一期 02B 的项目级总建筑面积、容积率、绿地率等不从模型自动计算。该延期不改变 02A 的构件扫描、语义确认、已有参数读取和构件属性写入职责。

### 6.4 预览与写入

写入前必须生成只读预览。用户确认后：

- 共享参数定义和绑定按参数独立准备；
- 构件字段以单个构件为原子单位写入；
- 同一构件任一字段写入或回读失败，该构件事务回滚；
- 其他构件继续，整体允许部分成功；
- 预览后文档、规则或构件发生变化时，相应预览失效。

## 7. 02B 项目实际指标

02B 是独立原生 Revit 功能，不与 02A 构件列表混合，也不提供自主选择。

### 7.1 第一期数据来源

第一期的项目实际指标由用户手工录入，不读取模型几何、不执行项目级面积汇总或比率计算。至少包括：

- 总建筑面积；
- 实际建筑密度；
- 实际容积率；
- 实际绿地率；
- 实际机动车位数量；
- 实际非机动车位数量。

字段身份固定为：

- 总建筑面积使用 `IfcProject / Pset_登记信息属性集 / 总建筑面积`；
- 实际建筑密度、容积率和绿地率使用 `IfcSite / Pset_场地信息属性集`中的对应属性；
- 实际机动车位和非机动车位数量使用 `IfcSpatialZone / Pset_停车场信息属性集`中的对应属性；
- `IfcProject / Pset_项目控制指标信息属性集`中的同名字段只表示规划目标或配置要求，不得承载上述实际值。

02B 表单必须覆盖总平清单中所有“项目级实际值且第一期来源为人工录入”的规则项。该集合由唯一规则源确定，并作为可版本化、可测试的生成清单固化；不得在 UI 中另建手工字段字典。

若某个实际指标的官方 Revit 载体尚未得到证实，系统必须显示载体证据阻断，不能因为 UI 已能录入就猜测载体或宣称官方插件可导出。

每个值记录来源为 `人工录入`，并保留准确字段身份、单位、录入时间、文档身份、规则版本、写入结果和回读结果。

后续增加模型自动计算时，只新增数据提供者并替换来源；02B 字段身份、UI、写入协议和 Stage03 检查协议保持不变。

### 7.2 指标级事务

02B 采用“指标级提交、局部回滚、成功保留”：

- 每个指标独立校验、写入和回读；
- 成功指标立即保留；
- 失败指标只回滚自身，不影响其他成功指标；
- 失败后残留的旧参数值可以保留，但标记为“本次未成功更新”；
- Stage03 不得将该旧值视为本次有效结果；
- UI 允许只重试失败指标。

未来恢复全模型自动计算时，每次计算仍必须基于完整项目重新计算全部指标；写入继续采用上述指标级事务。

## 8. 共用问题中心

02A、02B 和 Stage03 复用稳定的问题编号和处理入口。

### 8.1 问题等级

- **阻断：** 缺少清单要求的构件或数据、语义未确认、几何/值无效、参数冲突、写入或回读失败、结果过期；
- **警告：** 低置信度候选、人工修改系统建议值、非阻断技术提示；
- **通过：** 当前检查项满足合同并完成回读。

### 8.2 构件问题定位

构件存在时，每条问题显示问题原因、语义角色、构件名称、类别、ElementId、关联字段或指标，并提供：

- 选中构件；
- 缩放到构件；
- 临时隔离；
- 恢复视图；
- 修复后单项复查；
- 重新执行当前批次。

缺失必要构件时没有可定位对象。UI 必须显示缺少的语义角色、需要它的检查项、允许的载体类型和自动识别候选，并提供进入 02A 选择或补充构件的入口。

项目字段或项目指标缺失时，直接打开 Stage01 或 02B 的对应输入位置。

## 9. Stage03 检查清单

### 9.1 清单生成

模型类型只在 Stage01 选择。Stage03 自动读取该模型类型、武汉规则基线和项目覆盖规则，生成当前模型的检查清单，避免重复选择导致不一致。

第一期为总平模型生成清单。清单内项目不得人工标记不适用；缺失必要构件或数据即为红色失败。

### 9.2 清单分组

- Stage01：项目登记、坐标和规划条件；
- 02A：构件语义、构件属性、写入和回读；
- 02B：项目实际指标、写入和回读；
- 跨阶段：文档身份、规则版本和数据时效性；
- 导出准备：IFC 参数和技术环境。

### 9.3 列表与状态

每条检查项显示：

`检查项名称 | 来源阶段 | 适用依据 | 当前值 | 状态 | 问题说明 | 处理入口`

状态颜色固定为：

- 灰色：尚未检查；
- 绿色：检查通过；
- 红色：未通过或缺失；
- 黄色：非阻断警告。

用户可以执行全部检查、单项复查，并从红色项目进入 Stage01、02A 或 02B。Stage03 不在本界面内代替来源阶段修改数据。

### 9.4 测试强制导出

测试强制导出必须：

- 使用明显的测试名称和视觉标识；
- 要求填写原因；
- 保留全部红色项目；
- 在报告和产物身份中标记测试导出；
- 只能绕过业务缺项，不能绕过技术错误；
- 不得被计为正常导出通过或官方验收通过。

## 10. 跨阶段数据合同

Stage01、02A、02B 和 Stage03 的结果至少携带：

- Revit 文档指纹；
- 当前模型类型；
- 规则 packageId、version 和 SHA-256；
- runId；
- 来源阶段和功能；
- 字段或构件 identity；
- 当前值、单位和来源；
- 写入和回读状态；
- 更新时间；
- 稳定结果 hash。

Stage03 必须拒绝将其他文档、其他规则版本、失败写入或已过期结果作为当前有效数据。

## 11. 自动化测试

### 11.1 规则和清单

- 总平模型清单可确定性生成；
- 清单只使用唯一规则源和受控 overlay；
- 同名字段的不同 IFC identity 不被合并；
- 第一期开启严格模式且无“不适用”入口；
- 模型类型只从 Stage01 读取。

### 11.2 Stage01

- 登记、坐标和规划目标字段分组正确；
- 总建筑面积只引用 02B，不在 Stage01 重复编辑；
- 目标值与实际值身份不混用；
- 类型、单位、写入和回读错误能准确阻断。

### 11.3 02A

- 全模型扫描与自主选择行为互不混淆；
- 自主选择不产生项目级指标；
- 自动候选必须人工确认；
- 构件级事务允许准确部分成功；
- 问题记录能定位正确 ElementId；
- 现有 v0.4.2 绿地写入能力不回退。

### 11.4 02B

- 实际指标以人工来源录入；
- 每个指标独立写入和回读；
- 一个指标失败只回滚自身；
- 成功项保留，失败项可单独重试；
- 旧值不会被 Stage03 当作本次成功值。

### 11.5 Stage03

- 灰、绿、红、黄状态稳定；
- 缺失构件、缺失数据和写入失败被准确分类；
- 构件问题能定位，缺失构件能进入 02A 补充；
- 项目问题能进入 Stage01 或 02B；
- 测试强制导出保留红色状态和测试标记；
- 技术错误无法被强制导出绕过。

## 12. Revit 2020 实机验收

至少使用三类 RVT 场景：

1. **空模型：** Stage03 完整列出总平检查项和预期红色项目，插件不崩溃；
2. **不完整模型：** 绿色和红色混合显示，02A 能定位已有问题构件，缺失构件能进入补充流程；
3. **Golden RVT：** 完成 Stage01、02A、02B、Stage03、保存重开和正式导出路径。

实机必须验证：

- 02A 全扫描和自主选择；
- 批量部分成功及构件级回滚；
- 02B 指标级部分成功及失败重试；
- 保存、关闭、重开后的持久性；
- 模型或关键输入变化后的过期识别；
- Stage03 单项复查和全部复查；
- 普通导出门禁与测试强制导出差异；
- 问题构件选中、缩放、隔离和恢复；
- 官方插件导出的 IFC 字段 identity、类型、单位和值；
- 官方检查器的版本、报告和截图。

只有同一 Golden RVT 完成“Revit 写入回读 → 官方插件导出 → 官方检查器识别”，才可声明官方全链路通过。

## 13. 非目标

第一期不包括：

- 地上建筑单体或地下建筑单体的完整清单交付；
- 从模型几何自动计算总建筑面积、建筑密度、容积率、绿地率或停车位数量；
- 允许用户将清单项目标记为不适用；
- 将测试强制导出作为生产通过；
- 猜测官方插件未证实的属性载体；
- 使用 Web、Grasshopper 或外部服务替代原生 Revit 插件；
- 将自动化测试通过等同于 Revit 或官方插件实机验收通过。

## 14. 完成标准

第一期只有在以下条件全部满足时才可声明完成：

1. Stage01 能录入、写入并回读总平项目输入和规划目标；
2. 02A 作为独立功能支持全模型扫描和自主选择；
3. 02A 支持候选语义、人工确认、构件级部分成功和问题定位；
4. 02B 作为独立功能支持项目实际指标手填、指标级提交和局部回滚；
5. Stage03 能按总平模型生成严格检查清单并正确显示颜色；
6. 红色问题能准确返回 Stage01、02A 或 02B；
7. 普通导出受门禁控制，测试强制导出具有完整测试标记；
8. 自动化测试、Release 构建和静态合同通过；
9. Revit 2020 完成空模型、不完整模型和 Golden RVT 验收；
10. 官方插件和官方检查器的结果被单独记录，不以内部写入成功冒充官方通过。
