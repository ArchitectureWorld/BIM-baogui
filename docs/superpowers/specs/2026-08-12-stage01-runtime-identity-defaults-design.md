# Stage01 真实运行身份与默认初始化 v0.9.1 设计

**状态：** 方案已确认，待书面规格复核后实施

**确认日期：** 2026-08-12

**目标环境：** Revit 2020 + Rhino 8 + Rhino.Inside.Revit + Grasshopper 8

**目标插件版本：** BIMBaoGui.Stage01 0.9.1

**开发分支：** `feat/stage01-runtime-identity-defaults-v0.9.1`

## 1. 目标

本增量只完成以下三项：

1. 在 01 卡片顶部直接显示当前 Grasshopper/Revit 实际加载程序集的插件版本、构建号、提交号和程序集路径；
2. 不新增“一键自测”入口，保留现有“执行校验”和“写入并回读”业务动作；
3. 将 01 中可以安全确定的必选项预设好，并将“无上述项目条件（已确认）”设为默认勾选，减少重复填写。

本增量不得用示例值或占位文本伪造项目事实。项目名称、项目编号、建设单位、设计单位、项目地址、组织信息等真实业务数据，只能来自当前 RVT、既有初始化记录或用户明确输入。

## 2. 当前问题

### 2.1 插件身份不可信

当前插件版本分别硬编码在：

- `Stage01AssemblyInfo.Version`；
- 项目文件的 Version/FileVersion/AssemblyVersion；
- 卡片页脚 `BIMBaoGui v0.9.0`；
- GitHub Actions 的版本校验与产物名称。

GitHub Actions 当前没有把 `github.run_number` 和 `github.sha` 写入程序集，因此界面无法回答“Revit 现在到底加载了哪一个构建”。只改安装目录或安装器说明不能解决旧 GHA/DLL 被继续加载的问题。

### 2.2 01 默认值不完整

唯一规则源中已经存在以下安全默认：

- 模型文件类型：`总平模型`；
- 模型范围：`项目总平面报规模型`；
- 坐标系名称：`CGCS2000`；
- 高程系名称：`1985国家高程基准`；
- 真北角度：`0`；
- 长度、面积、角度显示单位；
- 文件 GUID 和工作流系统字段。

但基点坐标 X、基点坐标 Y、基点高程仍为 `NONE`，项目条件全部默认为 false，且规则库中尚无“无上述项目条件（已确认）”这一明确声明。

### 2.3 规则语义可能自相矛盾

“无上述项目条件（已确认）”如果与道路红线、绿地、地下停车等实际条件同时为 true，会生成自相矛盾的 HBR_FileContext。因此该声明不能只是一个普通复选框，必须与其他项目条件互斥。

## 3. 方案比较

### 方案 A：继续在 UI 中硬编码版本与默认值

优点是改动最少；缺点是界面显示值可能与实际加载程序集不一致，规则默认值也会与唯一规则源漂移。拒绝采用。

### 方案 B：随插件部署独立 build-info.json

可以记录构建号和提交号，但侧车文件可能在复制、覆盖或手工安装时与 GHA 分离，无法证明当前加载程序集的真实身份。拒绝作为主方案。

### 方案 C：程序集运行时身份 + 唯一规则源默认策略

- 版本、构建号和提交号写入程序集元数据；
- 路径通过当前实际加载程序集的 `Assembly.Location` 获取；
- 01 默认值只修改 `hbr_rule_source.v1.json`，再由既有生成链重建嵌入规则库；
- UI 只消费运行时身份和规则模型，不维护第二份版本或默认值。

该方案是本增量的唯一实施方案。

## 4. 真实插件身份

### 4.1 数据来源

新增单一运行时身份对象，例如 `PluginRuntimeIdentity`，其数据固定来自：

| 显示项 | 权威来源 | 本地构建回退值 |
|---|---|---|
| 插件版本 | 当前加载程序集的 Assembly/File/Informational Version | 实际程序集版本 |
| 构建号 | AssemblyMetadata：`HBR.BuildNumber` | `local` |
| 提交号 | AssemblyMetadata：`HBR.CommitSha` | `unknown` |
| DLL/程序集路径 | 当前加载程序集的 `Assembly.Location` | 空路径时明确显示“运行时未提供路径” |

严禁从 UI 常量、安装目录猜测、文件名或 README 读取上述身份。

### 4.2 CI 注入

GitHub Actions 构建时向 MSBuild 传入：

- `HbrBuildNumber=${{ github.run_number }}`；
- `HbrCommitSha=${{ github.sha }}`。

项目文件将其生成为程序集 `AssemblyMetadataAttribute`。本地编译仍可成功，但必须明确显示 `Build local / Commit unknown`，不得伪装成 CI 构建。

### 4.3 顶部显示

卡片顶部固定展示三层信息：

```text
01 文件初始化                                      当前状态
插件 v0.9.1 · Build #123 · Commit abcdef12
DLL/程序集路径：C:\...\BIMBaoGui.Stage01.gha
```

约束：

- 信息来自 `typeof(Stage01Component).Assembly` 对应的当前实际加载程序集；
- 提交号显示前 8 位，完整值保留在运行时身份对象中；
- 实际产物扩展名为 `.gha` 时仍显示真实 `.gha` 路径，标签使用“DLL/程序集路径”以匹配用户表达并保持技术准确；
- 路径区域允许换行，优先完整显示，不以固定安装路径替代；
- 页脚移除硬编码 `BIMBaoGui v0.9.0`，避免顶部与页脚出现两个版本真相；
- `Stage01AssemblyInfo.Version` 改为读取实际程序集版本，不再写独立常量。

## 5. 01 默认策略

### 5.1 安全预设

以下默认值由唯一规则源提供，并在新建表单、重置表单以及缺失字段迁移时生效：

| 字段 | 默认值 | 处理 |
|---|---|---|
| 模型文件类型 | 总平模型 | 保留现有安全默认 |
| 模型范围 | 项目总平面报规模型 | 保留现有安全默认 |
| 报规文件唯一 ID | 新 GUID | 保留现有系统生成 |
| 坐标系名称 | CGCS2000 | 保留现有安全默认 |
| 高程系名称 | 1985国家高程基准 | 保留现有安全默认 |
| 基点坐标 X | 0 | 新增；X 继续表示南北坐标 |
| 基点坐标 Y | 0 | 新增；Y 继续表示东西坐标 |
| 基点高程 | 0 | 新增 |
| 真北角度 | 0° | 保留现有安全默认 |
| 长度显示单位 | m | 保留现有系统默认 |
| 面积显示单位 | m² | 保留现有系统默认 |
| 角度显示单位 | ° | 保留现有系统默认 |

坐标、高程和真北的 `0` 是初始化基线，不代表真实报规坐标已经核实。现有 Revit 读取与回读流程仍必须用活动文档的实际值覆盖或校验这些基线。

### 5.2 真实业务信息

下列数据不设置伪造默认：

- 项目名称、项目编号、项目地址；
- 建设单位、设计单位；
- 子项编号、子项名称；
- 参建组织、联系人和信用代码；
- 行政区划与报建联系人信息。

处理顺序固定为：

1. 优先读取当前 RVT 已存在的可信值；
2. 其次读取当前文件已有的 HBR 初始化记录；
3. 仍为空时保留为空并继续显示必填阻断；
4. 由用户补充后再执行“写入并回读”。

默认值不得覆盖已读取的非空真实值。

## 6. “无上述项目条件（已确认）”

### 6.1 规则身份

在唯一规则源的 `conditions` 中新增跨模型通用声明：

- `conditionId`: `common.none_confirmed`
- `displayName`: `无上述项目条件（已确认）`
- `group`: `10_项目条件`
- `activationRuleId`: `null`
- `defaultActive`: `true`

该条件只表达用户对当前可见条件清单的否定确认，不触发任何 Stage02 建模任务。

### 6.2 可见性

`common.none_confirmed` 在以下三类模型中始终可见：

- 总平模型；
- 单体建筑—地上；
- 单体建筑—地下。

其他条件仍按当前模型类型过滤。

### 6.3 互斥行为

交互规则固定为：

- 初始状态只勾选 `common.none_confirmed`；
- 用户勾选任一实际项目条件时，自动取消 `common.none_confirmed`；
- 用户重新勾选 `common.none_confirmed` 时，自动取消当前模型类型下所有实际项目条件；
- 切换模型类型后，若新模型类型没有任何实际条件为 true，则恢复 `common.none_confirmed = true`；
- 读取旧 GH/HBR 数据时，如果出现“无条件声明 + 实际条件”并存，迁移策略以实际条件为准并取消无条件声明，同时给出一次非阻断修复消息。

由此保证写入 HBR_FileContext 的条件集合不自相矛盾。

## 7. 不做的内容

本增量明确不做：

- 不新增“一键自测”按钮、菜单或外部诊断窗口；
- 不删除现有“执行校验”；
- 不跳过正式的写入与回读验证；
- 不自动填写项目和企业的虚构名称；
- 不改变 H-IFC Entity / PropertySet / Property / GUID 映射；
- 不修改 Stage02、Stage03 的业务范围；
- 不把运行时路径写死为某个用户目录。

## 8. 版本与规则包

- 插件版本从 0.9.0 升级为 0.9.1；
- 规则源默认行为发生变化，规则包按补丁版本升级并重建 manifest；
- 冻结的既有版本或 Tag 不移动、不覆盖；
- CI 产物名称、版本断言、程序集版本和 UI 运行时显示必须一致。

## 9. 测试与验收

实施采用测试先行。至少覆盖：

### 9.1 运行时身份

- 读取实际程序集版本；
- 正确读取构建号和提交号元数据；
- 本地构建缺少元数据时显示明确回退值；
- 路径来自当前程序集 `Location`；
- UI 和 `Stage01AssemblyInfo.Version` 不再含独立硬编码版本。

### 9.2 默认值

- 新建模型和重置表单得到 X=0、Y=0、高程=0；
- 现有模型类型、模型范围、坐标系、高程系、真北和单位默认保持不变；
- 真实非空 RVT/HBR 值不会被默认值覆盖；
- 项目名称、编号、组织等业务字段仍不会生成假值。

### 9.3 项目条件

- `common.none_confirmed` 默认 true；
- 三种模型类型均可见；
- 与实际条件双向互斥；
- 旧数据冲突可确定性修复；
- 该声明不激活任何 Stage02 任务。

### 9.4 CI

- Python 规则编译、schema、semantic、manifest 测试通过；
- .NET Core 测试通过；
- net48 GHA 编译通过；
- CI 反射校验版本、构建号和提交号；
- 最终产物仍为单一可安装 `BIMBaoGui.Stage01.gha`。

## 10. 验收标准

在 Revit 2020 + Rhino.Inside.Revit + Grasshopper 中打开 01 卡片时：

1. 顶部能直接看到当前实际加载插件版本、GitHub Actions 构建号、提交短 SHA 和真实 GHA/DLL 路径；
2. 不存在“一键自测”入口；
3. 新建或重置 01 表单时，安全必选项已填入；
4. “无上述项目条件（已确认）”默认勾选；
5. 勾选任一实际条件后该声明自动取消，反向操作也成立；
6. 当前 RVT 有真实项目数据时优先读取，读不到时不伪造；
7. 完整测试与 CI 构建通过后才生成可验收 GHA。
