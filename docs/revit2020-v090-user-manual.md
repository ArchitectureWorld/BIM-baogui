# BIMBaoGui v0.9.0 三组件使用与 IFC 导出说明

本文面向验收人员，说明如何在 Revit 2020 中依次使用三个 Grasshopper 组件，并导出原始 IFC 与 H-IFC 转译文件。

## 1. 使用前准备

- 软件环境：Revit 2020、Rhino 8、Rhino.Inside.Revit、Grasshopper。
- 待处理 RVT 必须已经保存，具有绝对文件路径。
- 当前活动插件位置：

```text
C:\Users\2899\AppData\Roaming\Grasshopper\Libraries\BIMbaogui\BIMBaoGui.Stage01.gha
```

- 插件目录只能保留一个 `BIMBaoGui.Stage01.gha`，不能存在 `.bak` 或 `.backup` 插件备份。
- 建议在操作前保存一次 RVT。

三个组件的执行顺序固定为：

```text
01 文件初始化
  -> 02 构件与属性准备
  -> 03 检测、导出与 H-IFC 转译
```

## 2. 启动顺序

1. 打开 Revit 2020，并打开需要验收的 RVT。
2. 在 Revit 中启动 Rhino.Inside.Revit。
3. 在 Rhino.Inside.Revit 中启动 Grasshopper。
4. 在 Grasshopper 菜单中进入 `湖北BIM报规 / 报规工作流`。
5. 放置以下三个公开组件：

```text
湖北BIM报规｜01 文件初始化
湖北BIM报规｜02 构件与属性准备
湖北BIM报规｜03 检测、导出与 H-IFC 转译
```

## 3. 组件 01：文件初始化

`01 文件初始化`没有 Grasshopper 输入端口。项目初始化内容在组件自身的卡片中填写。

操作步骤：

1. 放置 `湖北BIM报规｜01 文件初始化`。
2. 在组件卡片中依次检查或填写项目身份、坐标 X/Y、高程、真北、模型类型、项目条件和规划控制内容。
3. 进入卡片中的“提交与校验”区域，只勾选与当前 RVT 实际情况相符的确认项。
4. 点击卡片中的“写入并回读”。
5. 等待组件完成 Revit 写入与回读。

以下结果表示本阶段完成：

- `初始化通过 = True`；
- `状态 = 初始化通过`；
- “消息”中没有未处理的阻断；
- “文件上下文”端口输出有效的强类型 `HBR_FileContext`。

接线要求：

```text
01 的“文件上下文” -> 02 的“文件上下文”
01 的“文件上下文” -> 03 的“文件上下文”
```

必须连接“文件上下文”端口，不能把“上下文JSON”文本代替它。

## 4. 组件 02：构件与属性准备

本组件用于选择 Revit 载体、预览需要安装或写入的参数，并在确认后将参数和值写入 Revit。写入成功后，参数应能在 Revit 的项目信息或构件属性面板中直接看到和编辑。

### 4.1 输入端口

| 输入 | 用法 |
|---|---|
| 文件上下文 | 连接 `01 文件初始化`的“文件上下文”输出 |
| 元素Id | 可选；输入当前 Revit 文档中的 ElementId 列表 |
| 角色提示 | 可选；为本次所选元素指定统一角色提示 |
| 交互点选 | 设为 `true` 后，在“生成预览”出现 `false -> true` 上升沿时打开 Revit 点选 |
| 项目信息 | 处理 Revit 项目信息时设为 `true`；处理普通构件时设为 `false` |
| 生成预览 | 使用 Boolean Toggle 或 Button；每次新预览都要产生一次 `false -> true` 上升沿 |
| 确认写入 | 预览合格后产生一次 `false -> true` 上升沿，执行一次原子写入 |

### 4.2 处理项目信息

1. 将“项目信息”设为 `true`。
2. “元素Id”保持为空，“交互点选”保持 `false`。
3. 让“生成预览”从 `false` 切换到 `true`。
4. 检查“匹配载体”“字段明细”“阻断信息”“待安装数量”和“待写入数量”。
5. 没有必须处理的阻断后，先把“确认写入”保持或复位为 `false`，再切换为 `true`。
6. 等待“写入状态”与“总状态”显示成功。
7. 在 Revit 的“管理 -> 项目信息”中检查新增的 HBR 参数和值。

### 4.3 处理模型构件

可任选一种选择方式：

- 将 ElementId 列表接到“元素Id”；或
- 将“交互点选”设为 `true`，再触发一次“生成预览”的 `false -> true` 上升沿，到 Revit 中点选构件并结束选择。

完成选择后：

1. 查看“匹配载体”，确认识别到的构件和角色正确。
2. 查看“字段明细”和“阻断信息”。
3. 确认“待安装数量”和“待写入数量”符合预期。
4. 触发“确认写入”的 `false -> true` 上升沿。
5. 等待“写入状态”显示成功，并检查“已安装数量”“已写入数量”。
6. 回到 Revit，选中相同构件，在实例或类型属性面板中检查 HBR 参数是否可见、可编辑。
7. 保存 RVT。

如果修改了选择、角色、项目信息模式、RVT 或 Stage01 数据，旧预览可能显示“结果过期”。此时必须重新生成预览，不能继续确认旧预览。

## 5. 组件 03：检测、导出与 H-IFC 转译

本组件会扫描当前 Revit 文档，生成字段检查报告；门禁允许时，先使用 Autodesk Revit 标准 IFC4 导出 RAW IFC，再生成 HIFC-MVD IFC。

### 5.1 接线

| 输入 | 推荐接线 |
|---|---|
| 文件上下文 | 连接 `01 文件初始化`的“文件上下文”输出 |
| 执行 | 连接 Button 或 Boolean Toggle，只在 `false -> true` 上升沿执行一次 |
| 输出目录 | 连接 Panel，填写已经存在的绝对目录，例如 `D:\18_建模项目\2026.07_湖北银行报规\3D` |
| 全部通过才导出 | 连接 Boolean Toggle：`true` 为 Strict，`false` 为 Force |
| 强制原因 | Force 模式时连接 Panel，填写非空原因 |

输出目录必须是已经存在的绝对目录。程序不会覆盖同名正式产物。

### 5.2 Strict 模式

```text
全部通过才导出 = true
```

- 只要存在活动业务阻断，Strict 就不会发布 IFC。
- 这时仍会生成 `<RVT名>-<runId>-fields.json`，用于查看缺构件、名称不匹配、缺参数、空值或未分类等问题。
- 当前 v0.9.0 规则源为 `359/359 UNCLASSIFIED`，因此当前不要为了得到 Strict 成功结果而伪造分类。

Strict 操作：

1. 将“全部通过才导出”设为 `true`。
2. “强制原因”可以留空。
3. 确认输出目录正确。
4. 将“执行”复位到 `false`，再切换为 `true`。
5. 查看“状态”“全部阻断”和“fields JSON”路径。

### 5.3 Force 模式：当前验收导出 IFC 的方法

```text
全部通过才导出 = false
强制原因 = 任意非空、可审计的真实说明
```

推荐填写例如：

```text
v0.9.0 验收导出：当前规则分类尚未完成，保留全部业务阻断并测试 IFC 生成。
```

Force 操作：

1. 将“全部通过才导出”设为 `false`。
2. 在“强制原因”中填写非空说明。
3. 确认“输出目录”为已存在的绝对目录。
4. 将“执行”复位到 `false`。
5. 再让“执行”从 `false` 切换为 `true`。
6. 等待运行结束，不要重复点击。
7. 查看“RAW IFC”“HIFC-MVD IFC”“fields JSON”三个输出端口。

Force 只允许绕过业务阻断，不能绕过以下技术错误：

- 当前 Revit 文档或 FileContext 不一致；
- RVT 未保存或路径无效；
- 输出目录无效或目标文件冲突；
- Revit IFC 导出失败；
- IFC 解析、转译或回读失败；
- 字段报告或失败报告写入失败。

任何输入发生变化，包括 FileContext、输出目录、Strict/Force 模式或强制原因，都必须重新让“执行”产生一次 `false -> true` 上升沿。

## 6. 导出文件说明

Force 成功后，输出目录中应出现同一 `runId` 的三件套：

```text
<RVT名>-<runId>-RAW.ifc
<RVT名>-<runId>-HIFC-MVD.ifc
<RVT名>-<runId>-fields.json
```

| 文件 | 用途 |
|---|---|
| `-RAW.ifc` | Revit 2020 使用 Autodesk 标准 IFC4 导出的原始文件；后处理不会改写它 |
| `-HIFC-MVD.ifc` | 按 HBR/H-IFC 映射规则转译并回读检查后的 IFC |
| `-fields.json` | 本次字段检测、业务阻断、Force 原因、规则包身份和产物证据 |

判断导出成功时，至少检查：

- 组件“状态”不是技术失败；
- 三个输出端口都有绝对路径；
- 三个文件真实存在且不是空文件；
- 三个文件名包含同一个 `runId`；
- HIFC-MVD IFC 中需要验收的 X、Y、高程等字段与 Revit 可见值一致。

注意：Force 生成三件套只证明测试放行下完成了导出与转译，不代表 Strict 全部通过。

## 7. 导出失败时怎么处理

1. 先看组件“状态”和“全部阻断”。
2. 如果只有业务阻断：
   - Strict 下先根据 `fields.json` 修正模型或属性；或
   - 验收测试需要导出时，改为 Force 并填写非空原因。
3. 如果是技术失败：不要反复点击，也不要用 Force 强行绕过；记录“报告路径”或失败报告文件。
4. Stage01、Stage02、Stage03 的失败报告位于活动 GHA 同目录：

```text
C:\Users\2899\AppData\Roaming\Grasshopper\Libraries\BIMbaogui
```

常见文件名：

```text
BIMBaoGui.Stage01.failure-*.json
BIMBaoGui.Stage02.failure-*.json
BIMBaoGui.Stage03.failure-*.json
```

将失败报告、Grasshopper 截图、输出目录和当前 RVT 路径一起提供给开发人员。不要创建 GHA 备份文件，也不要把旧报告或其他 `runId` 的产物当成本次运行证据。
