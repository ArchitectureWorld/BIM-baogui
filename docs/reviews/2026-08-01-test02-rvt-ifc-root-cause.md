## 2. 结论

这组文件证明当前失败发生在官方插件导出之前：

1. RVT 中保存的是 Stage 01 `0.2.0` 初始化载荷，不是 v0.7.0 的正式参数写入结果；
2. RVT 内未发现任何 `HIFC.*` 参数名，也未发现 v0.7.0 候选共享参数 GUID；
3. IFC 中没有任何项目级 H-IFC PropertySet，所有属性集都只挂在一个 `IfcWall` 上；
4. 官方 H-IFC 插件没有得到可读取的项目级标准参数；
5. 对照已提取的官方配置，v0.7.0 还存在第二个结构性错误：只写 `HIFC.<属性集>.<属性>`，而官方配置在没有第三列别名时按 IFC 属性原名读取 Revit 参数。

因此，当前 RVT 必须先由修复版 GHA 升级并重新写入，再由官方插件生成一个新的 IFC。

## 5. 根因

### 根因 A：测试 RVT 仍是旧版初始化

当前 RVT 的工作流版本是 `0.2.0`。旧 GHA 只把表单写进 Extensible Storage，没有创建官方插件需要读取的正式 Revit 参数。

v0.7.0 原先又要求旧文件手动启用“允许重新初始化”，导致旧 RVT 容易保持旧载荷而没有执行新投影。

### 根因 B：v0.7.0 参数名称契约错误

已提取的官方规则中 166 条属性的 `sourceParameterOverride` 均为空。官方配置的语义是：

```text
有第三列源参数别名 → 读取该别名
没有第三列源参数别名 → 按 IFC 属性原名读取 Revit 参数
```

例如官方插件查找的是：

```text
项目名称
项目编号
基点坐标X
基点坐标Y
坐标系名称
高程系名称
```

v0.7.0 只创建：

```text
HIFC.申报信息属性集.项目名称
HIFC.申报信息属性集.项目编号
...
```

两者不一致。即使 v0.7.0 真正写入，官方插件仍可能找不到值。

### 根因 C：此前验收门槛停留在 Revit 回读

参数 GUID 回读只能证明 GHA 写入了自己创建的参数，不能证明官方插件读取的是同一个参数。当前 IFC 证明这两件事必须分开验证。

## 6. v0.8.0 修复

修复版采用双投影：

```text
内部唯一参数：HIFC.<PropertySet>.<Property>
官方源参数：  <sourceParameterOverride 或 IFC 属性原名>
```

包括：

- 自动把 `0.2.0`、`0.7.0` 等旧初始化升级到 `0.8.0`；
- 旧版升级不再要求启用“允许重新初始化”；
- Revit 已存在唯一的精确同名参数时直接复用；
- 不存在时创建确定性 GUID 的精确同名共享参数；
- 同时保留 `HIFC.*` 参数用于内部唯一标识和跨 PropertySet 防冲突；
- 对 `备注`、`建筑物编码` 等同一对象上多条规则共用同一个官方源名称的情况返回 `OFFICIAL_SOURCE_NAME_AMBIGUOUS`；
- 写入、Regenerate、双参数回读和失败回滚仍处于同一事务组。
