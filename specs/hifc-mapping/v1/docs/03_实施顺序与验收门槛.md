# 官方插件兼容写入实施顺序与验收门槛

> 本计划替代旧版自研 IFC 导出与后处理里程碑。当前产品只负责正确写入 Revit，IFC 由官方插件导出。

## M0：官方证据与实现假设分离

交付：

- 166 条规则载入与 schema 校验；
- 4 条官方显式对象映射；
- `official_plugin_compatibility_status.v1.json`；
- 官方证据、候选参数、Revit 回读、官方导出、检查软件五级状态。

验收：任何实现决策不得被标成官方提取；任何未完成官方导出实测的字段不得显示“官方兼容通过”。

## M1：Stage 01 全字段覆盖

交付：

- Stage 01 非空 IfcProject 字段注册表驱动投影；
- HBR 工作流字段与 IFC 标准字段分离；
- IfcOrganization 数据保留与明确阻断；
- 规划目标与实际指标分离；
- X=南北、Y=东西坐标修复。

验收：

- 所有非空 IfcProject 字段有映射或明确例外；
- 不再只依赖 10 个硬编码字段；
- 坐标回归测试使用不相等哨兵值；
- Organization 不会被压平伪写到 ProjectInformation。

## M2：对象安全写入

交付：

- IfcProject/IfcBuilding → ProjectInformation；
- IfcBuildingStorey → 明确 Level；
- IfcSpace → 明确 Room；
- 按每条属性分别解析目标；
- 未确认实体阻断策略。

验收：

- 楼层属性无法写入房间或 ProjectInformation；
- 空 ElementId 仅允许项目/建筑属性；
- 错误类别在写入前产生可操作诊断；
- Site/Organization/SpatialZone/Door/Duct 不再被静默宣称兼容。

## M3：参数、单位与原子事务

交付：

- Text、Integer、YesNo、Length、Area、Volume、Angle、Number；
- m/m²/m³/° 到 Revit 内部单位转换；
- TransactionGroup；
- GUID 回读；
- 整体回滚。

验收：故意制造错误类型、错误类别、错误值和只读参数，系统必须明确失败且不留下部分写入。

## M4：Project / Building 官方插件闭环

交付：

- Golden RVT 中的 IfcProject 与 IfcBuilding 哨兵字段；
- 官方插件导出的 Golden IFC；
- 检查软件报告；
- 导出 manifest。

验收：

```text
GH 值 = Revit 值 = 官方插件 IFC 值 = 检查软件识别值
```

只有通过的字段更新为 `OFFICIAL_EXPORT_VERIFIED` 与 `CHECKER_VERIFIED`。

## M5：Storey / Space 官方插件闭环

交付：

- 多个 Level 与 Room，使用不同哨兵值；
- 对象级参数写入；
- 官方插件导出；
- IFC 实体、Pset、属性和对象关系检查。

验收：楼层与空间属性不串对象，不丢失，检查软件逐项识别。

## M6：未确认实体协议研究

按优先级研究：

1. IfcOrganization；
2. IfcSite；
3. IfcSpatialZone；
4. IfcDoor；
5. IfcDuctSegment。

每个实体必须先确认官方插件的 Revit 读取协议，再开放 GHA 写入。禁止先根据常规 Revit/IFC 经验猜测宿主。

验收：每类实体都有独立 Golden RVT/Golden IFC 和检查报告；多个组织或多个区域不能互相覆盖。

## M7：指南需求等级合并

交付：

- 必填；
- 条件必填；
- 建议；
- 不适用；
- 后续模型计算；
- 外部项目数据导入。

验收：需求等级有指南或检查规则证据；官方示例值不得被当作默认值或必填证据。

## M8：完整回归与 GHA 交付

自动化：

- Python 契约测试；
- .NET 核心测试；
- Revit 2020 编译；
- GHA 程序集、大小和 SHA-256；
- 规则、字段、实体策略覆盖。

实机：

- Golden RVT；
- 官方插件导出 Golden IFC；
- 官方检查软件回归；
- 版本化导出 manifest。

最终 GHA 只有在自动化通过且目标实体完成官方软件闭环后，才能作为稳定兼容版交付。
