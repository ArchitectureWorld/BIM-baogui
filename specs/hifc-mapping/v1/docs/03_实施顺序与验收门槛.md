# 首版实施顺序与验收门槛

## M0：规则内核（先做，禁止先做界面）

交付：

- RulePackage Loader；
- JSON Schema 校验；
- 166 条规则载入；
- canonical ID / UUIDv5 生成；
- Rule Resolver 空壳，支持模型类型过滤接口。

验收：重复运行两次，166 个 propertyId 和参数 GUID 逐字节一致；任何重复 canonical key 立即失败。

## M1：Revit 对象图

交付：Project、Building、Storey、Space、Door、Duct、Site、Organization、SpatialZone 九类 CanonicalObject；Revit UniqueId 与 canonical objectId 的双向索引。

验收：关闭并重新打开 Revit 后 objectId 不变化；Level/Room 删除后产生明确悬空引用诊断。

## M2：数据存储与参数镜像

交付：Extensible Storage/DataStorage 主存储、确定性共享参数、参数绑定修复、单位转换、TransactionGroup、回读验证。

验收：故意制造同名参数、错误类型参数和错误 Category，系统必须准确识别并给出修复动作。

## M3：首个闭环实体

只做 `IfcBuilding` 的 17 条“建筑技术信息属性集”。

验收：ProjectInformation → Canonical BUILDING → Revit 参数镜像 → IFC Pset → IFC 复检 17/17；禁止一开始同时实现 166 条 UI。

## M4：空间层级

依次实现 IfcBuildingStorey、IfcSpace、IfcSite、IfcSpatialZone。

验收：楼层和空间关系正确；SpatialZone 能由 Area/成员关系生成，并在 IFC 中有明确关联。

## M5：项目与组织

实现 IfcProject、多个 IfcOrganization 以及参建关系。

验收：多个组织不会互相覆盖；企业属性进入各自 IfcOrganization，而不是全部挤在 ProjectInformation。

## M6：普通构件与导出

实现 IfcDoor、IfcDuctSegment，接入 Revit 原生 IFC 导出和 IFC 后处理。

验收：九类对象全部覆盖；166 条规则形成逐条 export manifest。

## M7：三层验证与官方软件回归

- 规则验证；
- Revit 模型验证；
- IFC 成果验证；
- 官方检查软件 Golden Sample。

验收：每次代码提交都对 Golden IFC 做回归；任何属性、实体、关系或单位变化必须显式审批。

## M8：交互界面

左侧固定阶段导航；右侧单页滚动；字段内示例为 placeholder；错误就地显示；模型对象可定位；所有阶段数据自动传递。

界面只能消费前面已经稳定的命令接口，不得重新实现业务规则。
